Предобработчик неструктурированной сетки meshdec
================================================

meshdec читает AEROMESH v2 из текстового, бинарного или сжатого файла и
записывает пространственно упорядоченные листья и каталог дерева в один
файл .mdec. В main.txt укажите этот архив в параметре mesh. Для одного
процесса aero поддерживает обычный расчёт из архива. На нескольких CPU-процессах
MPI доступны first_order, ebr3, ebr5, weno3 и weno5 по пространству, Эйлер и SSPRK3 по времени,
а также отдельный режим проверки геометрии --geometry-only.
Периодические пары задаются в bc.txt при запуске aero. Один архив можно
использовать для разных сочетаний периодических и физических границ.
На кластер достаточно перенести .mdec и текстовые
настройки задачи. Пример запуска приведён в ../../source/aero/README.txt.

Подготовка на домашнем ПК
-------------------------

  make meshdec
  ./bin/meshdec examples/tecplot/demo_3d.mesh grid.mdec --target-ranks=32

Утилита запускается одним процессом. В примере 32 — ожидаемое число
MPI-процессов будущего решателя на кластере. Параметр необязателен.
Скопируйте на кластер файл grid.mdec. Временные файлы нужны только во
время подготовки. Можно использовать архив и при другом числе процессов.

При --target-ranks=P предобработчик ориентируется примерно на четыре
листа с вершинами на будущий процесс. Несколько листьев дают решателю
свободу при назначении работы устройствам разной скорости. Для N исходных
вершин предел вершин в листе равен ceil(N / min(N, 4*P)). Дополнительно
действует предел байтов. Фактическое число листьев записано в заголовке.
Когда параметр опущен, нарезка определяется только размером записей.
Веса CPU и бюджеты памяти по узлам можно задать позднее в main.txt решателя
через mpi_rank_weights и mpi_node_memory_mib. При изменении этих параметров
тот же .mdec используется повторно.
Для каждого листа meshdec готовит три непересекающихся списка. Первый содержит все
ячейки при вершинах листа и нужен уже для first_order. Второй дополняет
первый до полной окрестности обоих концов каждого ребра для EBR3 и WENO3.
Третий добавляет для EBR5 и WENO5 ячейки, примыкающие к любой вершине первых
двух списков. Обе схемы ищут дальнюю опору в этом втором слое на продолжении того же ребра.
Для EBR и WENO решатель при запуске использует записанные связи вершин с гранями.
По ним можно найти грань, все вершины которой попали в слой, даже если сама
грань принадлежит ячейке за его пределами.
Если процессу достались соседние листья, общие ячейки читаются в одну
локальную копию. Координаты, грани и ячейки имеют по одной записи в архиве.

Для периодики в архиве есть отдельный индекс ячеек при вершинах вблизи
внешних границ. Он охватывает оба слоя пятого порядка. Имена пар и векторы переноса
выбираются в bc.txt при запуске. Чтобы заменить периодическую пару
физическими условиями или включить периодику по другой оси, достаточно
изменить bc.txt. Тот же файл .mdec подходит для обоих запусков.

Запуск на нескольких процессах
------------------------------

  make meshdec WITH_MPI=1
  mpiexec -n 4 ./bin/meshdec grid.mesh grid.mdec --target-ranks=32 --temp-dir=/shared/scratch

Здесь четыре процесса выполняют предобработку. Их число берётся из
MPI_COMM_WORLD. В Linux можно так же запускать через mpirun -np 4.
Для сборки используется MPI_CXX=mpicxx. В Windows нужны Microsoft MPI
SDK и runtime, а также переменные MSMPI_INC и MSMPI_LIB64. Обычная сборка
работает без MPI и CUDA. В решении msvs/aero.sln имеются проекты meshdec
и meshdec_tests для Debug и Release, платформа x64. Для MPI-сборки MSBuild
передайте /p:WithMPI=true. В корневом Makefile meshdec входит в programs.

Параметры ввода и вывода
------------------------

  meshdec INPUT.mesh OUTPUT.mdec [--target-ranks=N] [--leaf-bytes=N]
          [--memory-mib=N] [--temp-dir=DIR] [--compress]

--leaf-bytes задаёт целевой максимум несжатого содержимого листа, по
умолчанию 4194304 байта. Запись одной вершины, грани или ячейки остаётся
целой. Если она превышает этот предел, ей выделяется отдельный лист.

--memory-mib задаёт размер серии внешней сортировки на процесс, по
умолчанию 64 МиБ. Дополнительно расходуется память на небольшие страницы
таблиц, потоки ввода-вывода и, при сжатии, словарь LZMA. Реальный расход
памяти зависит также от платформы и библиотеки MPI.

--temp-dir указывает существующий каталог. По умолчанию используется
каталог результата. Для нескольких узлов он и каталог результата должны
находиться на общей файловой системе с одинаковыми путями для всех
процессов и поддержкой одновременной записи в непересекающиеся диапазоны.
Первый процесс читает исходный файл. Для временных таблиц, серий сортировки
и упакованных данных требуется дополнительное место на диске. Его объём
зависит от числа связей и может в несколько раз превышать размер входа.
Временные таблицы используют машинное представление чисел. Для совместной
предобработки нужны процессы с совместимым представлением данных.

--compress сжимает каждый лист отдельным потоком AEROLZMA с контрольными
суммами блоков. Каталог остаётся доступным для прямого чтения.
Целевой файл должен быть новым. Он публикуется из временного каталога
на том же томе после успешной записи всех частей. В POSIX для публикации
используется жёсткая ссылка. При ошибке программа возвращает код 1.

Построение
----------

1. Процесс 0 последовательно читает разделы AEROMESH и сохраняет таблицы
   на диске. Обратные связи вершина — грани и грань — ячейки строятся
   внешней сортировкой пар. Проверяются границы индексов, размеры строк,
   граничные метки и ориентации общих граней. Исходная сетка предполагается
   топологически корректной, как после mesh_converter.
2. Для вершины вычисляется 63-битный ключ Мортона по её трём координатам
   в ограничивающем параллелепипеде сетки, по 21 биту на ось. У грани
   ключ равен минимуму ключей её вершин, у ячейки — минимуму по граням.
   Совпадения разрешаются по типу сущности и исходному номеру. В MPI-режиме
   процессы сортируют свои диапазоны, выбирают пространственные разделители
   по выборке и упорядочивают записи внутри выделенных диапазонов.
3. Процесс 0 проходит упорядоченные описания, размечает листья и строит
   дисковую таблицу адресов. Каждый процесс упаковывает свою группу листьев,
   включая координаты, исходные номера, ориентации и ссылки через разрез.
   Списки ячеек для геометрии и обоих слоёв реконструкции строятся внешней сортировкой связей
   вершина — ячейка и концов рёбер между листьями. При объединении повторные
   ссылки удаляются. Полная сетка и индексы соседства помещаются на диск.
4. По готовым длинам групп и листьев вычисляются смещения. Процесс 0
   записывает каталоги, затем каждый процесс пишет свой диапазон полезных
   данных в общий файл. Для одинакового входа и параметров число процессов
   подготовки не влияет на порядок записей и границы листьев.

Двоичный формат AERODEC1, версия 4
----------------------------------

Все смещения в байтах. Целые числа — uint64 little-endian, вещественные —
IEEE binary64 little-endian. Нумерация с нуля. Пустая ссылка в каталогах
обозначается UINT64_MAX. Между полями записей нет выравнивания.

Заголовок занимает 136 байт. После восьмибайтовой сигнатуры AERODEC1 идут
следующие 16 восьмибайтовых полей.

  version, flags, dimension, length_scale_to_meters,
  nodes, faces, cells, boundary_faces, patches,
  leaves, tree_entries, root, names_offset, leaf_index_offset,
  tree_offset, payload_offset.

length_scale_to_meters — вещественное поле. Бит 0 в flags означает
независимое сжатие листьев. В пустом архиве leaves и tree_entries равны
нулю, root равен UINT64_MAX. Раздел имён содержит для каждой метки
длину и байты UTF-8 в исходном порядке.

Запись индекса листа состоит из шести полей и занимает 48 байт.

  absolute_offset, packed_bytes, raw_bytes, nodes, faces, cells.

Запись дерева занимает 112 байт.

  first_leaf, leaf_count, left, right, raw_bytes, nodes, faces, cells,
  xmin, ymin, zmin, xmax, ymax, zmax.

left и right — номера записей дерева, у листьев оба поля равны UINT64_MAX.
Дети записаны раньше родителя. Для непустого архива дерево содержит
2*leaves-1 записей. Габариты включают все вершины геометрии записанных
сущностей, даже если вершина принадлежит другому листу. Координаты и
габариты даны в исходных единицах сетки.

Между последней записью дерева и payload_offset расположен индекс halo.
Первые два uint64 задают суммарные числа адресов S и H в его двух таблицах.
Далее следуют четыре массива в указанном порядке.

  offsets[nodes+1], star_addresses[S],
  offsets[2*leaves+1], leaf_addresses[H].

Смещения в этих двух массивах offsets измеряются в записях адресов.
Строка i занимает диапазон [offsets[i], offsets[i+1]). В первой таблице
i — исходный номер вершины. Непустые строки хранят все примыкающие
ячейки для вершин в приграничной полосе. Чтобы построить полосу, берутся
концы рёбер, касающихся внешней границы, все ячейки при этих концах и все
вершины таких ячеек. Во второй таблице
строка 2*i хранит основной список ячеек листа i, строка 2*i+1 —
дополнительные ячейки ближнего слоя. Списки упорядочены по исходному номеру
ячейки. Каждый адрес состоит из двух uint64. Индексы читаются выборочно
и остаются несжатыми при --compress.

Начиная с версии 3 за этими массивами следуют число адресов F (uint64) и таблица

  far_offsets[leaves+1], far_addresses[F].

Строка i содержит дальний слой EBR5 и WENO5 для листа i. Смещения измеряются в
адресах. Ячейки, уже записанные в одном из двух списков листа, пропускаются.

В версии 4 сразу после far_addresses и перед первым листом записаны 64
строчных шестнадцатеричных символа SHA-256 исходной сетки в каноническом
формате AEROMSHB v2. meshdec вычисляет сумму при распаковке исходной сетки.
Сумма одинакова для текстового, бинарного и сжатого представлений одной
сетки и при изменении параметров разбиения. Она связывает архив с глобальным
файлом начальных полей и с файлами recovery.

Архивы версий 1 и 2 читаются для геометрии, однопроцессного расчёта и
распределённого first_order. Версия 2 также подходит для MPI с EBR3 и WENO3.
Для MPI с EBR5 и WENO5 нужен архив версии 3 или новее. Его можно один раз подготовить
из исходной .mesh на одном процессе независимо от будущего запуска MPI.

Все листья ветви лежат подряд. Чтобы прочитать ветвь, прочитайте её запись
по адресу tree_offset + 112*номер. Первая запись индекса листьев находится
по адресу leaf_index_offset + 48*first_leaf. По первой и последней записям
можно одним чтением получить весь диапазон. При сжатии декодируйте каждый
лист отдельно в пределах его packed_bytes.

Записи внутри листа начинаются с пары kind, original_id. Остальные поля
определяются значением kind.

  0 (вершина)   x, y, z, число граней, адреса инцидентных граней.
  1 (грань)     исходный номер в boundary_faces, номер метки, число вершин,
                число ячеек, адреса вершин в исходном порядке, адреса ячеек.
                Для внутренней грани оба граничных поля равны UINT64_MAX.
  2 (ячейка)    число граней, затем для каждой грани её адрес и один байт
                ориентации, 0x01 или 0xff. Порядок граней сохранён.

Адрес содержит два uint64 — номер листа и смещение записи от начала его
несжатого содержимого. Обратные ссылки позволяют найти соседние ячейки
без обхода всей сетки. Производные рёбра можно восстановить по исходным
вершинам и связности, как в Mesh. Периодические отождествления и поля
течения относятся к конкретному расчёту.

Проверки
--------

  make meshdec-test
  make meshdec-debug-test

Тесты сравнивают координаты, ориентации, граничные метки, прямые и обратные
ссылки с исходными сетками в 1D, 2D и 3D. Проверяются внешнее слияние с
малым буфером, разные числа исполнителей, независимое чтение сжатых
листьев, одна и несколько ветвей, пустой архив и повреждённый вход.
