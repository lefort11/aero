visfield — экспорт в бинарные Tecplot 360 и VTK Legacy
===================================================

Из корня проекта:
  bin/visfield.exe grid.mesh grid.plt
  bin/visfield.exe grid.mesh result_000100.fields result_000100.plt
  bin/visfield.exe grid.mesh result_000100.fields result_000100.plt --threads 4
  bin/visfield.exe grid.mesh grid.vtk
  bin/visfield.exe grid.mesh result_000100.fields result_000100.vtk
  bin/visfield.exe slice.submesh slice.fields slice.vtk
  bin/visfield.exe --help

Аргументы командной строки:
  MESH        внутренняя сетка AEROMESH v2/v3 или файл среза .submesh
  FIELDS      необязательный файл полей AEROFIELDS v1
  OUTPUT      выходной путь. Расширение .vtk выбирает VTK, .plt — Tecplot.
              При другом расширении сохраняется прежний режим Tecplot.

Для .vtk используется двоичный UNSTRUCTURED_GRID в формате Legacy 4.2.
В ParaView откройте .vtk, нажмите Apply и выберите нужное поле.
Узловые и ячеечные величины записываются в POINT_DATA и CELL_DATA, каждая компонента
своим скаляром double. Для полей рёбер и граней добавляются элементы соответствующей
размерности. Значения вне их размещения заполняются NaN. Номер шага входит в заголовок,
время записывается в массив TIME. Параметр --threads управляет подготовкой Tecplot.
Описание общей реализации находится в source/io/visualization/README.md.

При вызове с двумя путями для .plt создаётся статическая зона Cells с координатами
X, Y, Z и связностью исходных отрезков, полигонов или многогранников.

На входе автоматически распознаются Text, Binary и Lzma независимо от
расширений. Все сочетания кодировок сетки/полей поддерживаются.
При нехватке аргументов печатается краткая справка в stderr, код возврата 1.
--help/-h: справка в stdout, код 0. Ошибка чтения/проверки/записи: код 1.
Готовый PLT или VTK заменяет прежний выходной файл после успешной записи. Пути входных файлов и ссылки на них защищены.
Пути используют узкую строковую кодировку платформы, как существующие утилиты.

Проверка и преобразование
------------------------
Перед экспортом сравниваются SHA-256, размерность и количества сущностей сетки
и файла полей. Проверяется топология Mesh и структура FieldSnapshot.
Координаты X,Y,Z берутся непосредственно из сетки и сохраняются
для всех размерностей. Значения полей и строки единиц не пересчитываются.
При экспорте в Tecplot время записывается в SolutionTime, шаг — в Aero.Step.
Оба режима сохраняют SHA-256 сетки в метаданных зоны.
Каждый компонент поля становится отдельной переменной float64.

Основная зона Cells:
  1D -- FELINESEG, в том числе неравномерная сетка;
  2D -- FEPOLYGON, произвольные полигоны, включая вогнутые;
  3D -- FEPOLYHEDRON, произвольные многогранники, тетраэдры, призмы, гексы.
Разбиение элементов на треугольники/тетраэдры не выполняется.
Сохраняются номера узлов/элементов, циклы граней и их соседние элементы.
Для 3D используется наружная ориентация грани относительно левого элемента,
для 2D -- ориентированный контур. Требуется геометрически корректная ориентация
сетки: исправление отрицательных объемов или самопересечений не выполняется.

Поля NODE записываются как узловые, CELL -- как ячеечные в основной зоне.
Если присутствуют другие привязки, добавляются зоны:
  Edges -- FELINESEG, один элемент на ребро в исходном порядке, поля EDGE;
  Faces -- 1D: упорядоченный набор точек, поля FACE как узловые;
           2D: FELINESEG, один элемент на грань;
           3D: FEPOLYGON, один поверхностный полигон на грань.
В 1D зону Faces следует отображать точками (Scatter); упорядоченный набор
имеет неявный порядок, и отображение линиями соединит последовательные точки.
В 3D вершины поверхностных полигонов дублируются, чтобы каждый полигон был
независимым и не возникала неоднозначная смежность на ребрах объёмной сетки.
Узловые поля доступны во всех зонах; при дублировании узлов значения переносятся
по их исходным ID. Другие поля активны только в своей зоне. В остальных зонах
они помечены passive; интерполяция или усреднение не выполняется.
Зоны Edges/Faces создаются только при наличии полей соответствующей привязки.
Граничные метки исходной сетки не превращаются в отдельные зоны в этой версии.

Имена переменных:
  X, Y, Z
  v1:node:velocity.x [m/s], v2:node:velocity.y [m/s], ...
Префикс vN гарантирует уникальность, включая поля с одинаковыми именами
на разных сущностях. Для слишком длинных названий подпись сокращается до
128 байт по границе UTF-8 символа. Полные имя поля, компонент, единицы и
привязка сохраняются в auxiliary data соответствующей переменной.

Формат вывода и ограничения
---------------------------
Бинарный PLT v112, сигнатура #!TDV112, little-endian, данные BLOCK/float64.
Это готовый файл Tecplot с сеткой и полями. TecIO и установленный Tecplot
для работы утилиты не требуются. Формат реализован по официальной спецификации:
  https://tecplot.azureedge.net/products/360/current/360-data-format.html
  раздел Binary Data File Format

Полигональные и полиэдральные зоны предназначены для Tecplot 360;
Tecplot Focus такие зоны не поддерживает. Формат SZL здесь не используется.
Размеры/индексы проверяются на ограничения INT32 формата v112. Слишком большие
сетки отклоняются до создания файла. Пустая сетка не экспортируется.
NaN/Inf в полях вызывают ошибку:
утилита не заменяет диагностические значения нулями.
CLI использует штатные MeshReadLimits/FieldReadLimits. Для увеличенных лимитов
можно загрузить сетку/поля библиотечным API и вызвать aero::tecplot::write().

OpenMP
------
Включен по умолчанию. --threads N задает положительное число потоков.
Без --threads используются настройки OpenMP, в том числе OMP_NUM_THREADS.
В библиотечном Options значение threads=0 означает настройки среды исполнения.
Утилита не меняет глобальные настройки OpenMP.
Распараллелены подготовка координат и связности, проверка/диапазоны переменных
и упаковка блоков значений в выходной порядок байтов. Запись файла, чтение,
SHA-256 и LZMA остаются последовательными. Для малых массивов работает один поток.
Порядок данных не зависит от числа потоков. GPU для экспорта не требуется.

Сборка GNU Make (из корня, C++11):
  make visfield
  make visfield-test
  make visfield-debug-test
  make visfield WITH_OPENMP=0
  make visfield-test WITH_OPENMP=0

Без OpenMP --threads 1 разрешен, больше 1 вызывает понятную ошибку.
Цели make all/test/debug-test включают сборку и проверки утилиты.
Из utils/visfield можно использовать локальный Makefile с целями all/test/debug-test.

MSVS:
  открыть msvs/aero.sln; проекты visfield и tecplot_tests.
  OpenMP задается через msvs/openmp.props, по умолчанию включен.
  /p:WithOpenMP=false отключает; /p:RunTecplotTests=false отключает запуск тестов.
  Утилита и тесты публикуются в bin.
  Сборка без OpenMP: подкаталог serial внутри соответствующей конфигурации.
  Разные каталоги исключают использование устаревшего файла при смене варианта.

Тесты
-----
Тестовый читатель разбирает бинарные записи по спецификации и проверяет
размеры, расположение/значения полей, диапазоны, смежность, индексы, метаданные
и точное окончание файла. Есть 1D/2D/3D, внутренние грани, большие полигоны,
все комбинации входных кодировок, ошибки CLI/данных и повторную запись.
Результаты при одном и двух потоках сравниваются побайтово на больших сетках.
Открытие результата в самом приложении Tecplot в рамках этих тестов не выполняется.
