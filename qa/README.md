# Проверки aero по точным решениям

Из корня проекта выберите процессор для полного прогона. По умолчанию используется CPU.

```sh
python qa/run.py --backend cpu
python qa/run.py --backend cuda
```

Нужны Python 3.8 или новее и программы проекта `aero` и `fields_to_tecplot`. Пакеты Python устанавливать не требуется. Обе программы собирает `make programs`. Скрипт ищет их в `bin`, а на Windows также в `build/msvs/x64/Release` и его подкаталоге `cuda-sm86`. Выбранные пути печатаются перед расчётом. Свою сборку можно указать через `--aero ПУТЬ --fields-to-tecplot ПУТЬ`.

Для GPU нужна CUDA-сборка решателя (`make programs WITH_CUDA=1`). По умолчанию выбирается устройство 0. Например, `python qa/run.py --backend cuda --device 1` запускает набор на втором видимом устройстве. Каждый расчёт подтверждает активное устройство в строке `OK`. Если решатель перешёл на CPU, скрипт завершает прогон с кодом 1. Оба режима используют одни и те же начальные условия, сетки, эталоны и файлы допусков.

## Постановки

Во всех задачах газ идеальный, γ = 1.4. В каждом каталоге `qa/cases/<задача>` есть готовая сетка `grid.mesh`, параметры расчёта `main.txt`, свойства газа `gas.txt`, начальные данные `init.txt`, граничные условия `bc.txt`, расписание записи `output.txt` и допуски `tolerances.json`. Каждый каталог можно непосредственно передать решателю через `--input`.

| Задача | Сетка (ячейки) | Конечное время | Постановка и точное решение |
|---|---:|---:|---|
| `pulse_1d` | 96 | 0.20 | Гладкий периодический импульс плотности. Профиль переносится вправо со скоростью 1 при постоянном давлении. |
| `sod_1d` | 201 | 0.12 | Задача Римана Сода. Слева от 0.5 заданы (ρ, u, p) = (1, 0, 1), справа (0.125, 0, 0.1). Открытые торцы. К моменту сравнения волны находятся внутри области. |
| `momentum_2d` | 8 × 48 | 0.24 | Гладкий периодический перенос поперечного импульса. При ρ = 1 профиль скорости uₓ равен 0.3 + 0.2 sin(2π(y − 0.75t)). |
| `shear_jump_2d` | 6 × 64 | 0.20 | Два сдвиговых разрыва. Полоса с повышенным uₓ переносится со скоростью 0.85 вдоль y и за время расчёта пересекает периодическую границу. |
| `wave_3d` | 14 × 14 × 14 | 0.14 | Гладкая пространственная волна плотности. Профиль зависит от всех трёх координат и переносится с вектором скорости (0.8, −0.6, 0.45). |
| `contact_3d` | 6 × 6 × 40 | 0.20 | Слой газа с ρ = 1.4 в среде с ρ = 1. Две плоские контактные поверхности перемещаются вдоль z со скоростью 0.8. Давление и все три скорости постоянны. |

Область имеет единичную длину вдоль каждой оси. Кроме задачи Сода, границы периодические по всем осям. Эталоны вычисляются в исходных узлах сетки на конечный момент времени. Для Сода `exact.py` находит давление за ударной волной из условия совпадения скоростей на контакте, затем вычисляет автомодельное решение во всех областях, включая веер разрежения.

## Схемы и допуски

На каждой гладкой задаче проверяются `first_order`, `ebr3`, `ebr5`, `weno3` и `weno5`. На каждой разрывной задаче проверяются `weno3` и `weno5`. Каждая реконструкция запускается со всеми комбинациями переменных (`conservative`, `characteristic`, `flux`), потоков (`roe`, `lf`) и схем по времени (`euler`, `ssprk3`). Полный набор содержит 252 расчёта.

Для ρ, каждой компоненты скорости, давления и плотности полной энергии E проверяются две абсолютные ошибки. В `tolerances.json` каждой величине соответствует пара `[максимум, средняя]`. Максимум берётся по всем узлам, включая фронты. Средняя — это сумма модулей ошибок с весами узловых контрольных объёмов, делённая на объём области. Секция `default` задаёт основные пределы, секция с именем реконструкции переопределяет их для неё. Для схемы первого порядка в гладких задачах предусмотрены отдельные допуски.

Одна задача с её штатными допусками:

```sh
python qa/run.py --case sod_1d
```

Единый абсолютный допуск на максимальную узловую ошибку можно передать через `--tol`. Проверка средней ошибки сохраняет пределы задачи:

```sh
python qa/run.py --case pulse_1d --tol 0.01
```

## Прогресс и результаты

Перед запуском каждого расчёта выводятся его номер, общее число запусков, имя задачи и схемы. После успешной проверки печатаются максимальная и средняя ошибки каждого поля. Строка `FAIL` указывает причину, а при превышении максимума также поле, значение ошибки, допуск и координаты узла. Скрипт продолжает остальные расчёты и возвращает код `1`, если хотя бы один завершился ошибкой. При успехе последняя строка — `OK: all 252/252 runs passed.`, код возврата `0`.

По умолчанию результаты CPU лежат в `qa/output/<задача>/`, результаты GPU — в `qa/output/cuda/<задача>/` независимо от текущего каталога при запуске. Имя файла включает все четыре настройки схемы, например `qa/output/cuda/sod_1d/weno5_characteristic_roe_ssprk3.plt`. Каждый файл содержит сетку, численные поля, поля `exact_*` и знаковую разность `error_* = численное − точное`. Превышение допуска также сохраняет файл для разбора. Повторный запуск обновляет соответствующие файлы. Параметр `--output КАТАЛОГ` меняет корень результатов, подкаталог `cuda` для GPU создаётся и в нём.
