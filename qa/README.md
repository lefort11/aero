# Проверки aero

## Как устроен каталог

`qa/cases/` содержит входные данные. `run.py` запускает собранный решатель для выбранных задач и схем, читает итоговые поля и сравнивает их с точными решениями из `exact.py`. Допуски задаются в каталоге каждой задачи. Остальные сценарии можно запускать отдельно. Многие из них готовят маленькую сетку и настройки во временном каталоге под конкретную проверку.

| Сценарии Python | Что проверяют |
|---|---|
| `run.py`, `linear_euler.py`, `curved_stencil.py` | Ошибку решения в узлах, перенос линейных возмущений, реконструкции IJK и PL на криволинейной сетке. |
| `viscosity.py`, `turbulence.py`, `sa_convection.py` | Затухание вязкого сдвига, стенку, струю из покоя с SA, модели турбулентности и порядок конвективного переноса SA на гладком решении. |
| `mpi_euler.py`, `mpi_periodic.py`, `mpi_geometry.py`, `mpi_balance.py` | Совпадение полей после разбиения сетки, периодические границы, геометрию контрольных объёмов и распределение работы между процессами. |
| `mpi_fields.py`, `mpi_recovery.py` | Общий файл полей в исходной нумерации и продолжение расчёта при смене числа процессов. |
| `mpi_gpu.py`, `mpi_gpu_scaling.py`, `mpi_timing.py` | Выбор карт и корректность результата, время на одной и двух GPU, содержимое таблицы времени. |
| `local_step_neighbors.py` | Согласование локальных шагов на рёбрах, местное ограничение по невязке и сравнение полей CPU, GPU и MPI. |
| `steady_multigrid.py` | Мультигрид совместно с LTS. Проверяются принятие поправок по пространственной невязке, продолжение из recovery и расчёт RANS SA. Сценарий поддерживает CPU, GPU и два процесса MPI. |
| `stabilization.py`, `first_order_start.py`, `run_control.py` | Откат шага, переключение с первого порядка, команды во время расчёта и остановку с сохранением. |
| `output_diagnostics.py`, `completion_forecast.py`, `settings_warnings.py` | Производные и дополнительные поля, в том числе Cp на стенке, прогноз завершения и сообщения о настройках. |

`exact.py`, `mpi_common.py` и `mdec_header.py` — вспомогательные модули с формулами эталонов, общими средствами запуска и чтением заголовка архива сетки. Модульные тесты C++ лежат рядом с проверяемыми модулями в `source/` и `utils/`, их общие заголовки и тестовые ядра Kokkos — в `tests/`. Например, `make viscosity-test` проверяет вязкую невязку и якобиан, а `qa/viscosity.py` запускает полноценные расчёты собранным солвером.

## Запуск сверки с точными решениями

Из корня проекта выберите процессор для полного прогона. По умолчанию используется CPU.

```sh
python qa/run.py --backend cpu
python qa/run.py --backend cuda
```

Нужны Python 3.8 или новее и программы проекта `aero` и `fields_to_tecplot`. Пакеты Python устанавливать не требуется. Обе программы собирает `make programs`. Скрипт ищет их в `bin`, а на Windows также в `build/msvs/x64/Release` и его подкаталоге `cuda-sm86`. Выбранные пути печатаются перед расчётом. Свою сборку можно указать через `--aero ПУТЬ --fields-to-tecplot ПУТЬ`.

Для GPU нужна CUDA-сборка решателя (`make programs KOKKOS_BACKEND=cuda`). По умолчанию выбирается устройство 0. Например, `python qa/run.py --backend cuda --device 1` запускает набор на втором видимом устройстве. Каждый расчёт подтверждает активное устройство в строке `OK`. Если решатель перешёл на CPU, скрипт завершает прогон с кодом 1. Оба режима используют одни и те же начальные условия, сетки, эталоны и файлы допусков.

## Постановки

Во всех задачах газ идеальный, γ = 1.4. В каждом каталоге `qa/cases/<задача>` указан путь к сетке и есть параметры расчёта `main.txt`, свойства газа `gas.txt`, начальные данные `init.txt`, граничные условия `bc.txt`, расписание записи `output.txt` и допуски `tolerances.json`. Каждый каталог можно непосредственно передать решателю через `--input`.

| Задача | Сетка (ячейки) | Конечное время | Постановка и точное решение |
|---|---:|---:|---|
| `pulse_1d` | 96 | 0.20 | Гладкий периодический импульс плотности. Профиль переносится вправо со скоростью 1 при постоянном давлении. |
| `sod_1d` | 201 | 0.12 | Задача Римана Сода. Слева от 0.5 заданы (ρ, u, p) = (1, 0, 1), справа (0.125, 0, 0.1). Открытые торцы. К моменту сравнения волны находятся внутри области. |
| `momentum_2d` | 8 × 48 | 0.24 | Гладкий периодический перенос поперечного импульса. При ρ = 1 профиль скорости uₓ равен 0.3 + 0.2 sin(2π(y − 0.75t)). |
| `shear_jump_2d` | 6 × 64 | 0.20 | Два сдвиговых разрыва. Полоса с повышенным uₓ переносится со скоростью 0.85 вдоль y и за время расчёта пересекает периодическую границу. |
| `wave_3d` | 14 × 14 × 14 | 0.14 | Гладкая пространственная волна плотности. Профиль зависит от всех трёх координат и переносится с вектором скорости (0.8, −0.6, 0.45). |
| `contact_3d` | 6 × 6 × 40 | 0.20 | Слой газа с ρ = 1.4 в среде с ρ = 1. Две плоские контактные поверхности перемещаются вдоль z со скоростью 0.8. Давление и все три скорости постоянны. |
| `linear_acoustic_1d` | 96 | 0.032 | Линеаризованные уравнения. Периодический звуковой сигнал вдоль x. |
| `linear_acoustic_2d` | 8 × 48 | 0.032 | Звуковая волна вдоль диагонали (1,1). Проверяются обе компоненты скорости. |
| `linear_acoustic_3d` | 14 × 14 × 14 | 0.032 | Звуковая волна вдоль пространственной диагонали (1,1,1). Проверяются все три компоненты скорости. |

У линейных задач фон покоится, плотность и скорость звука равны единице. Сравниваются пульсации плотности, скорости, давления и энергии. Запуск трёх задач отдельно: `python qa/run.py --case linear_acoustic_1d --case linear_acoustic_2d --case linear_acoustic_3d`.

Область имеет единичную длину вдоль каждой оси. Кроме задачи Сода, границы периодические по всем осям. Эталоны вычисляются в исходных узлах сетки на конечный момент времени. Для Сода `exact.py` находит давление за ударной волной из условия совпадения скоростей на контакте, затем вычисляет автомодельное решение во всех областях, включая веер разрежения.

В `sod_1d/bc.txt` оба торца имеют тип `free`. Правила `superin`, `inflow` и `outflow` используют внутренние данные. Проверки граничного потока в `make bc-test` дополнительно задают разные входные и выходные данные на одной метке и проверяют переключение при смене скорости, включая обе звуковые границы и остановку потока.

## Схемы и допуски

На разрывных задачах проверяются `weno3`, `weno5`, `mp5` и `MPWENO5`. В гладких задачах к ним добавляются `first_order`, `ebr3` и `ebr5`. Для MP5 и для всех схем в задаче Сода используется `characteristic`. Для остальных сочетаний проверяются `characteristic` и `flux`. Для каждой комбинации проверяются оба потока (`roe`, `lf`) и обе схемы по времени (`euler`, `ssprk3`). Для Сода это 16 расчётов, для всего набора — 384 на каждом бэкенде.

Для ρ, каждой компоненты скорости, давления и плотности полной энергии E проверяются две абсолютные ошибки. В `tolerances.json` каждой величине соответствует пара `[максимум, средняя]`. Максимум берётся по всем узлам, включая фронты. Средняя — это сумма модулей ошибок с весами узловых контрольных объёмов, делённая на объём области. Секция `default` задаёт основные пределы, секция с именем реконструкции переопределяет их для неё. Для схемы первого порядка в гладких задачах предусмотрены отдельные допуски.

Одна задача с её штатными допусками:

```sh
python qa/run.py --case sod_1d
```

Единый абсолютный допуск на максимальную узловую ошибку можно передать через `--tol`. Проверка средней ошибки сохраняет пределы задачи:

```sh
python qa/run.py --case pulse_1d --tol 0.01
```

## Проверка MPI на CPU

`make mpi-fields-test WITH_MPI=1` сравнивает общий бинарный `.fields` с однопроцессным выводом по каждой исходной вершине, включая периодические копии. Тест запускает новую задачу на двух процессах из снимка четырёх процессов, проверяет пустые подобласти и совместную работу локальных и общих зон.

Сквозной тест `make mpi-recovery-test WITH_MPI=1` сравнивает запуск из глобальных полей TEXT, binary и LZMA и продолжение с другим числом процессов с непрерывным расчётом. Проверяются обе копии recovery, откат при обрыве файла и при повреждении записи отдельного узла, а также вывод по физическому времени. На линии из 8192 вершин с перемешанной нумерацией тест проверяет коллективный MPI-IO при переходе с двух процессов на три. Поля сравниваются с однопроцессной записью для каждой исходной вершины, включая вершины, попавшие в последующие порции чтения и записи.

`make mpi-balance-test WITH_MPI=1` сравнивает геометрию и поля периодической
задачи WENO5 при весах 1:3, 3:1 и 1:3:2:2 на одном архиве. Проверяются
пустые ранги, архив версии 1 и отказ до загрузки сетки при малом бюджете.
В `aero-test` распределение по узлам с неравной памятью дополнительно
сравнивается с перебором допустимых разрезов на небольшой сетке.

Для проверки распределённого CPU-решателя выполните `make mpi-euler-test WITH_MPI=1`
для явного Эйлера или `make mpi-ssprk3-test WITH_MPI=1` для SSPRK3.
Тест готовит архив на одном процессе и сравнивает шаги, поля и отчёты при 1, 2 и 4
процессах с обычным расчётом по исходной сетке. Проверяются скачок Сода на разрезе,
наклонная двумерная сетка, трёхмерная задача и запуск с пустыми подобластями.
Для SSPRK3 на первом полном шаге проверяется баланс массы, импульса и энергии
по трём слоям вершин с каждой стороны скачка. Снимки по шагам и физическому
времени сравниваются также в соседних копиях вершин.

`make mpi-periodic-test WITH_MPI=1` проверяет переносы в 1D, 2D и 3D для
обеих схем по времени. Проверяются равенство значений на шве, масса и энергия
в замкнутой области, смешанные границы, пересечение нескольких пар в углу
и периодическая ячейка с рёбрами, замыкающимися на одну расчётную вершину.

Цели `mpi-ebr3-test`, `mpi-ebr5-test`, `mpi-weno3-test` и `mpi-weno5-test`
запускаются через `make` с `WITH_MPI=1` и сравнивают каждую реконструкцию
с однопроцессным расчётом на исходной сетке.
Проверяются поля на каждом полном шаге, CFL,
отчёты и число сторон с пониженным порядком. Один архив наклонной сетки
используется с периодикой по двум осям, по одной и с физическими границами.
На периодической линии из восьми ячеек результат первого шага Эйлера
сравнивается с явной формулой потока EBR5 или с нелинейной формулой WENO3/WENO5.
Для WENO проверяются разрыв Сода на границе двух процессов и треугольная
сетка с невыпуклой окрестностью вершины, распределённая по семи процессам.

Тесты периодики также сверяют отчёт о разбиении с каталогом листьев и
числом расчётных вершин и рёбер однопроцессного решателя. На линии и сетках
с физическими границами объём пересылки потоков проверяется по владельцам
концов каждого ребра. Для каждого узла сверяются суммы памяти его процессов.

`make mpi-timing-test WITH_MPI=1` проверяет число замеров потоков, обновлений стадий, обменов, CFL и записи файлов на 1, 2 и 4 процессах для Эйлера и SSPRK3. Тест сверяет статистику после перезапуска и при продолжении с нулём новых шагов. Цель `mpi-gpu-test` также выполняет эти проверки на одной и двух GPU, включая совместное копирование для вывода и recovery.

`make mpi-gpu-test WITH_MPI=1 KOKKOS_BACKEND=cuda` сверяет поля двух физических GPU с однопроцессным CPU-решателем, включая периодику WENO5/SSPRK3, пустую подобласть и продолжение из recovery. Тест ограничивает память одной карты, проверяет перераспределение листьев по точному размеру массивов WENO и сверяет результат с CPU. Отдельно проверяется отказ до записи файлов, если целый лист превышает лимиты обеих карт. Для выбора карт при прямом запуске `qa/mpi_gpu.py` укажите, например, `--devices=1,0`.

Тест двух GPU также сверяет границу подобластей с измеренными весами и стоимостью каждого листа в каталоге `.mdec`. Проверяются автоматические и ручные веса, уменьшение калибровочной задачи при ограничении видеопамяти и назначение единственного листа более быстрой карте.

### Проверка распределённых BDF1 и BDF2

`make mpi-bdf1-test WITH_MPI=1` сверяет каждую строку произведения матрицы на вектор
с результатом на цельной сетке, затем проверяет линейную невязку BiCGSTAB и поля после
шагов Ньютона. Проверяются оба значения `simplified_jacobian`, скачок на стыке разделов,
принятие шага при исчерпании итераций Ньютона и пустые MPI-разделы. Для сравнения CPU с двумя картами
используйте `make mpi-bdf1-test WITH_MPI=1 KOKKOS_BACKEND=cuda MPI_BDF1_DEVICES=0,1`.

## Прогресс и результаты

Перед запуском каждого расчёта выводятся его номер, общее число запусков, имя задачи и схемы. После успешной проверки печатаются максимальная и средняя ошибки каждого поля. Строка `FAIL` указывает причину, а при превышении максимума также поле, значение ошибки, допуск и координаты узла. Скрипт продолжает остальные расчёты и возвращает код `1`, если хотя бы один завершился ошибкой. При успехе последняя строка — `OK: all 252/252 runs passed.`, код возврата `0`.

По умолчанию результаты CPU лежат в `qa/output/<задача>/`, результаты GPU — в `qa/output/cuda/<задача>/` независимо от текущего каталога при запуске. Имя файла включает все четыре настройки схемы, например `qa/output/cuda/sod_1d/weno5_characteristic_roe_ssprk3.plt`. Каждый файл содержит сетку, численные поля, поля `exact_*` и знаковую разность `error_* = численное − точное`. Превышение допуска также сохраняет файл для разбора. Повторный запуск обновляет соответствующие файлы. Параметр `--output КАТАЛОГ` меняет корень результатов, подкаталог `cuda` для GPU создаётся и в нём.

Цель `mpi-bdf2-test` проверяет переменный шаг BDF2, полный и упрощённый якобианы Роу и CSGS. Параметры MPI и список GPU те же, что для BDF1.

В `make mpi-bdf1-test` входит проверка выхода на стационар. На разрыве Сода
она измеряет начальную абсолютную норму пространственной невязки, задаёт
эквивалентные относительный и абсолютный пороги и сверяет шаг останова и поля
на всей сетке. Отдельно проверяются запись при исчерпании лимита, равномерное
начальное поле и сохранение результата между запланированными сроками вывода.

## Линеаризованные уравнения Эйлера

`make WITH_MPI=1 mpi-linear-test` сравнивает результат обычного запуска и двух процессов MPI с точным переносом двух акустических возмущений и возмущения энтропии. Проверяются все схемы реконструкции и знаки пульсаций, включая энергию. Для WENO3 сценарий повторяет расчёт на более грубой сетке. Двумерный и трёхмерный тесты переносят поперечную скорость на наклонном фоне. Отдельно проверяются нулевое решение в steady и продолжение BDF2 из контрольной точки.

Для сверки CPU с двумя GPU задайте `make WITH_MPI=1 KOKKOS_BACKEND=cuda MPI_BDF1_DEVICES=0,1 mpi-linear-test`.

MPI-сценарии задают совместные параметры `--mpi` и `--gpu` через `mpi_common.backend_parser`. Сценарии с единственной картой принимают `--device`, сценарии со списком — `--devices`. Для записи изменённых параметров `main.txt` используется `run.write_settings`, сохраняющая порядок ключей.
