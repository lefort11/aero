Параллельные обходы CPU и GPU
=============================

При сборке с CUDA 13 патч third_party/kokkos-3.2.01-compat.patch передаёт
в cudaMemPrefetchAsync номер GPU через cudaMemLocation. Для CUDA 12
используется прежняя сигнатура с целым номером устройства.

prediction_execution.h отбирает грани для локальной газовой подстановки на одном разделе
при steady RANS с автоматическим локальным шагом. Список использует свободную память
поправки Ньютона. Полную нелинейную невязку проверяет неявный интегратор.

GNU Make включает OpenMP по умолчанию. Сборка WITH_OPENMP=0 помещает результаты
в build/serial. В проектах Visual Studio соответствующее свойство — WithOpenMP.
Размер команды можно задать через OMP_NUM_THREADS.

Для новых CPU-модулей используйте parallel_for.h при обходе независимых строк.
Каждая итерация получает собственную область записи. Исключения выдаются после
завершения команды с приоритетом наименьшего индекса. Для коротких диапазонов
действует последовательный обход. Независимые индексы
на CPU распределяет kokkos_host.h. На NVIDIA и AMD device_work.cpp запускает обходы
Kokkos для потоков, стадий и минимума CFL. Формулы одной площадки и одного
узла находятся в соответствующих модулях солвера и используются на CPU, NVIDIA и AMD. Выбор карт, поиск PCI-адресов, получение объёма VRAM и создание внешних очередей используют runtime CUDA или HIP через device_platform.h.

Для двумерной MPWENO5 в характеристиках с потоком Роу и mp6_hybrid=0
полезно начать с process_mpweno_edges в device_faces.h. На больших сетках он
вызывает три функции из mpweno5_edges.h в порядке передачи данных. project
строит пять наклонов ребра в одном базисе Роу. reconstruct получает левый и
правый след каждой волны и поручает расчёт нелинейных весов свободным потокам
той же группы. write_flux переводит следы обратно и записывает поток по номеру
ребра. Формула весов находится в weighted_value в reconstruction/mpweno5.h.

При STATIC_LINK=1 графическая часть входит в исполняемый файл. Компилятор
присваивает её внутренним C++-символам Kokkos отдельное пространство имён,
поскольку у CPU и GPU разные типы исполнителей. Границу между ними задаёт device_work.h.

Параллельные обходы используются при построении связности сетки, подготовке
геометрии реконструкции, медианных объёмов и периодических связей, вычислении
начальных полей, сборке невязки, расчёте CFL и обновлении явной стадии.
В эйлеровских солверах и граничных условиях параллелизм обеспечивается обходом
рёбер и граничных площадок. Утилиты используют его при обработке наборов граней
и подготовке данных Tecplot. Текстовые значения AEROFIELDS форматируются блоками.
Запись блоков в файл, порядок нумерации и порядок суммирования вкладов фиксированы.

Численные специализации и точки перехода между CPU и GPU перечислены в SPECIALIZATIONS.md.
device_execution.h запускает типизированные операции run_rows в стандартном потоке выбранной карты.
device_check.h преобразует статус драйвера в результат интерфейса C и обрабатывает отсутствие карты.

row_loop.h принимает исполнитель Kokkos, диапазон и численную операцию. Для CPU
короткий диапазон проходит последовательно. Для GPU в политике запуска сохраняются
ограничения размера блока и HintLightWeight. Переданные указатели принадлежат вызывающему модулю.
