# Специализации CPU и GPU

Карта охватывает все точки входа `aero_device_*` из `device_api.h` и `device_work.h`. Для каждой операции таблица указывает файл с хостовой реализацией, общей формулой или вызывающим кодом. Точки входа определены в [device_work.cpp](device_work.cpp) и [device_runtime.cpp](device_runtime.cpp). Имя GPU в таблице приведено без общего префикса `aero_device_`.

| Операция | Точки входа GPU | Код хоста или общая формула | Различия исполнения |
|---|---|---|---|
| CSGS | `pack_csgs`, `csgs_color`, `csgs_image` | [matrix_execution.h](../implicit/matrix_execution.h) | Упаковка и произведение используют общие функции pack и image. CsgsSweep обрабатывает одну строку. GPU распределяет строки одного цвета между потоками, CPU обходит локальные поддомены в порядке зависимостей. |
| Предобусловливатель Якоби | `jacobi_allocate`, `jacobi_release`, `jacobi_factor`, `jacobi_apply` | [matrix_execution.h](../implicit/matrix_execution.h) | Общие factor и solve. При вырожденном блоке редукция возвращает номер первой ошибки. Размещение и освобождение факторов выполняет владелец памяти. |
| Матрица газа | `spatial_faces`, `spatial_rows`, `time_diagonal`, `spatial_apply` | [matrix_execution.h](../implicit/matrix_execution.h) | Общая сборка производных, строк, временной диагонали и умножение. Разбиение строки по компонентам определяется при компиляции для данного исполнителя. |
| Вязкий якобиан | `viscous_matrix` | [row_execution.h](../viscosity/row_execution.h) | Общий MatrixAssembly собирает вклад в столбец, при наличии компактной геометрии использует плитки и существующий кэш градиентов. |
| BiCGSTAB | `krylov_reduce`, `krylov_project`, `krylov_update`, `krylov_update_norm` | [BdfLinearSystem::Storage](../implicit/bicgstab.cpp) | Векторные обновления и редукции в bicgstab_vectors.h параметризованы исполнителем. У GPU сохраняются свой Range и привязка устройства. |
| Ньютон и история BDF | `newton_residual`, `newton_update`, `time_prediction` | [residual_norm, update, extrapolate](../implicit/bdf1_step.cpp) | Общие NewtonUpdate, TimePrediction и локальная формула нормы. apply_rows выбирает исполнитель перед циклом, measure_rows запускает локальную редукцию и согласует её результат между рангами. |
| Локальная подстановка газа | `local_gas_prediction` | [prediction_execution.h](../implicit/prediction_execution.h) | Одна функция отбирает грани префиксной суммой и вычисляет потоки короткого списка. Список переиспользует поправку Ньютона. CPU передаёт описание пакета в памяти хоста, GPU использует постоянное описание раздела на устройстве. |
| Многосеточная коррекция | `multigrid_transfer`, `multigrid_update` | [CoarseStep::transfer, update](../multigrid/coarse_step.cpp) | Общие Transfer и VectorUpdate. Буферы остаются у владельца. |
| Характеристические потоки | `faces` | [face_execution.h](../residual/face_execution.h) | Общий диспетчер и набор ядер для пакетов, сокращённых и полных шаблонов, физических границ. Хостовая оболочка переводит номер отказа в сообщение об ошибке. |
| Нормали граней | `normals` | [euler_unit_direction](../eulersolver/euler.h) | GPU заранее заполняет массив единичных нормалей для упакованной геометрии. Математическая операция нормирования общая. |
| Сумма потоков | `gather` | [face_execution.h](../residual/face_execution.h) | gather_flux_batch собирает все уравнения узла по инцидентным граням. Первую ошибку отмечает общая операция. |
| CFL | `wave_step`, `flux_step` | [MinimumStep, host_min](../timestep/cfl_detail.h) | Редукция общей пары шага и номера узла. На CPU малые задачи проходят последовательно, на GPU сохраняется переданный поток. Для FluxCfl хостовая точка входа находится в residual/residual.cpp. |
| LTS и связь с невязкой | `stencil_rates`, `local_steps`, `limit_local_steps`, `neighbour_steps` | [LocalSteadySteps, LimitLocalSteps, NeighbourStepSweep, StencilRates](../aero/partition_operator.cpp) | Одни узловые операторы применяются на обеих платформах. step_execution.h объединяет запуск вычисления шага, ограничения и соседнего прохода. |
| Явная стадия | `stage` | [stage_execution.h](../explicit/stage_execution.h) | update_field выполняет FieldStageUpdate и отмечает отказ по общему флагу. |
| Узлы раздела | `owned_stage`, `failed_nodes` | [partition_execution.h](../aero/partition_execution.h) | Общее обновление узла и проверка допустимости. При отдельном сборе отказов CPU возвращает хостовый вектор, GPU резервирует позиции в списке атомарно. |
| Обмен MPI | `records` | [partition_execution.h](../aero/partition_execution.h) | transfer_records использует одну операцию записи и чтения. CPU сохраняет последовательность записей, GPU упаковывает параллельно в буферы раздела. |
| Стационарный отчёт | `steady_report` | [Report::measure_values, FlowSummary::add_squares](../io/report.cpp) | На CPU блоки и накопление в long double, на GPU полосы в рабочем буфере Ньютона и double. Общие формулы выбора поля и масштабированных квадратов. |
| Моменты и производная давления | `sample`, `pressure_rate` | [sample_accepted, output_pressure_rate](../aero/partition_operator.cpp) | Общие diagnostic::Sample и partition_detail::PressureRate. GPU может вернуть на хост только запрошенное поле. |
| Перенос SA | `sa_convection`, `sa_step`, `sa_norm` | [step_execution.h](../turbulence/step_execution.h) | Общие конвекция, релаксация, сборка локального дефекта и редукция максимума. CPU может читать элементный кэш диффузии. Упакованный путь использует существующие плитки WENO. |
| Вязкость AES | `viscosity`, `prepare_tetra_volumes` | [row_execution.h](../viscosity/row_execution.h) | evaluate выполняет подготовку газа, фильтра, материала и вязких строк. При компактном представлении использует аффинные или координатные плитки. Подготовка объёмов вызывается для представления тетраэдрального разбиения. |
| Среда выполнения | `shutdown` | [host_parallel::Runtime](../parallel/kokkos_host.h) | Завершение Kokkos зависит от владения средой. У GPU есть собственные контексты и поток для каждой карты. |

## Специализированные ядра и хранение данных

- [device_faces.h](device_faces.h) и [mpweno5_edges.h](mpweno5_edges.h) содержат общий для CPU и GPU обход полных и неполных шаблонов и командную реконструкцию MPWENO5. Общий расчёт упакованной грани находится в [packed_weno.h](../residual/packed_weno.h).
- [device_affine_aes.h](device_affine_aes.h) и [device_volume_coordinates.h](device_volume_coordinates.h) используют командную память GPU и разную геометрию ячейки. Формулы парных коэффициентов и объёмной части напряжений находятся в [grad.h](../viscosity/grad.h).
- [reconstruction.cpp](../reconstruction/reconstruction.cpp) хранит хостовое представление ReconstructionContext. Через четыре отдельные точки входа [reconstruction_gpu.cpp](../reconstruction/reconstruction_gpu.cpp) он узнаёт число устройств, создаёт копию шаблона, получает её представление и освобождает её. Общие формулы реконструкции принимают ReconstructionStencilView и работают с памятью выбранного исполнителя.
- [report_explicit.cpp](../io/report_explicit.cpp) читает принятое поле через inspect на CPU и через снимок state на GPU. Оба пути передают значения в одни и те же функции Report.
- [partition_gpu.cpp](../aero/partition_gpu.cpp) отвечает за размещение и копирование полей, [reconstruction_gpu.cpp](../reconstruction/reconstruction_gpu.cpp) — за размещение шаблона. Эти расходы зависят от адресного пространства и времени жизни данных.
- [device_platform.h](device_platform.h) связывает операции с нативными API CUDA и HIP. Типы ошибок, закреплённая память и представление стандартного потока задаются выбранной платформой.
- [device_cases.cpp](../../tests/device_cases.cpp) содержит точки входа тестовых ядер для сопоставления с результатами хостовой реализации. Они не участвуют в расчётном шаге.
- [MP5](../reconstruction/mp5.h), [MPWENO5](../reconstruction/mpweno5.h) и [WENO](../reconstruction/weno.h) используют общий код сравнения интервалов и вычисления весов. Представление чисел зависит от упаковки шаблона. [Проверка конечности](../eulersolver/euler.h) читает показатель степени binary64, [обратная величина SA](../turbulence/model_math.h) использует две поправки Ньютона в нормальном диапазоне. Эти операции одинаковы на CPU и GPU.

При проверке состояния Ньютона на полном локальном поле оба исполнителя сохраняют проверенный газ в существующем буфере граней. При разбиении с обменом кэш заполняется после обновления копий соседних узлов. Вязкий оператор выбирает осреднение материала с известным числом вершин для однородных сеток и общий обход для смешанных.
