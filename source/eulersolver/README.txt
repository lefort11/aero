Эйлеровские солверы ЛФ и Роу
============================

Модуль source/eulersolver, C++11, идеальный газ gamma>1, 1D/2D/3D.
Один вызов -- одна пара реконструированных состояний, один численный поток.
Обход сетки, OpenMP, запуск CUDA, площади контрольных поверхностей, граничные
условия, сборка невязки, ограничители и шаг по времени принадлежат верхнему уровню.
Модуль независим от mesh, reconstruction и io.

Файлы
-----
euler.h/.cpp -- общие состояния, EulerStatus/EulerError/EulerFluxResult,
               физический поток Эйлера и построение базиса Роу.
characteristic.h/.cpp -- переходы между U и W в замороженном базисе Роу.
lax_friedrichs.h/.cpp -- локальный ЛФ (Русанов).
roe.h/.cpp -- классический Роу с модулем собственных значений.
eulersolver_tests.cpp -- CPU-тесты и верхнеуровневый тестовый драйвер.
eulersolver_cuda_tests.cu -- настоящие CUDA-вызовы обоих солверов и перехода.
Численные функции в заголовках имеют __host__ __device__; дублирующих GPU-формул нет.
Файлы .cpp содержат проверяемые CPU-перегрузки со std::vector и сообщения ошибок.

Общий контракт
--------------
U = [rho, rho*u_1, ..., rho*u_d, E], число компонент d+2.
E -- полная энергия на единицу объема, не удельная.
d задает размерность физической системы; импульсы и direction используют
один декартов базис. Размерность Mesh автоматически не подставляется.
direction содержит d компонент и нормируется внутри:
  n=direction/|direction|.
Его длина НЕ является площадью. Выход -- поток на единицу площади.
Нулевое направление недопустимо. Площадь прикладывается при сборке невязки.

Все солверы принимают готовые состояния/потоки, не удвоенные приращения.
Верхний уровень сначала восстанавливает:
  U_L=U_i+delta2_L/2, U_R=U_j-delta2_R/2,
или аналогичные значения W_L/W_R либо F_L/F_R.
Возвращается общий EulerFluxResult:
  components = d+2,
  flux[0 .. d+1] -- поток; неактивные элементы массива flux[5] нулевые,
  max_wave_speed -- оценка скорости сигнала, без площади.
Для ЛФ это max(|u_n,L|+c_L, |u_n,R|+c_R).
Для Роу дополнительно учитывается max|lambda_Roe|: на скачке поперечной
скорости звуковая скорость Роу может превысить обе исходные оценки.

ЛФ (Русанов)
------------
  F*=(F_n(U_L)+F_n(U_R))/2 - alpha*(U_R-U_L)/2,
  alpha=max(|u_n,L|+c_L, |u_n,R|+c_R).
Физический поток:
  p=(gamma-1)*(E-|rho*u|^2/(2*rho)), c=sqrt(gamma*p/rho),
  F_n(U)=[rho*u_n, rho*u*u_n+p*n, (E+p)*u_n].

CPU с локальными std::vector:
  #include "lax_friedrichs.h"
  auto result = aero::lax_friedrichs_conservative(U_L, U_R, direction, gamma);
  auto result = aero::lax_friedrichs_fluxes(F_L, F_R, U_L, U_R, direction, gamma);

Второй вариант использует именно переданные F_L/F_R в центральном среднем.
Это реконструированные физические потоки вдоль ЕДИНИЧНОЙ n, не тензоры
и не раздельные LF-потоки F+ и F-. U_L/U_R нужны для скачка и диссипации.
Переданные потоки не заменяются на F_n(U_L/U_R).

Роу
---
  #include "roe.h"
  auto result = aero::roe_conservative(U_L, U_R, direction, gamma);
  auto result = aero::roe_fluxes(F_L, F_R, U_L, U_R, direction, gamma);

  F*=(F_L+F_R)/2 - R*|Lambda|*R^{-1}*(U_R-U_L)/2.
R и Lambda строятся по средним Роу РЕКОНСТРУИРОВАННЫХ U_L/U_R.
Амплитуды скачка вычисляются аналитически, без численного обращения матрицы.
В варианте roe_fluxes матрица и скачок по-прежнему определяются U_L/U_R,
а центральное среднее берется из заданных F_L/F_R.

Реализован классический модуль lambda. Энтропийной поправки, ограничения
положительности и автоматического переключения на ЛФ нет. В частности,
трансзвуковое разрежение требует отдельного решения об энтропийной поправке.
Физичность входов проверяется, но она не гарантирует физичность всех
промежуточных состояний классического Роу или будущего шага по времени.

Внешний характеристический переход
----------------------------------
Солверы больше не выполняют переход W -> U внутри себя. Общий порядок:
  #include "characteristic.h"
  #include "roe.h" // или lax_friedrichs.h

  aero::EulerRoeBasis frozen;
  auto status = aero::euler_roe_basis(
      d, U_i.data(), U_j.data(), direction.data(), gamma, &frozen);
  // Здесь обязательно проверить status.
  auto U_L = aero::characteristic_to_conservative(frozen, W_L);
  auto U_R = aero::characteristic_to_conservative(frozen, W_R);
  auto result = aero::roe_conservative(U_L, U_R, direction, gamma);

Для ЛФ последняя строка заменяется на lax_friedrichs_conservative.
Замороженный базис реконструкции строится по ИСХОДНЫМ U_i/U_j и один для
всех точек шаблона ребра. Диссипативный базис Роу строится позже по U_L/U_R.
Эти два базиса в общем случае различны; нельзя подменять один другим.

W означает линейные компоненты W=R^{-1}U, не нелинейные инварианты Римана.
Нормировка/порядок столбцов R:
  0: акустика минус [1, u_bar-c_bar*n, H_bar-c_bar*(u_bar dot n)],
  1: энтропия       [1, u_bar, |u_bar|^2/2],
  2 .. d: сдвиг    [0, t_k, u_bar dot t_k] (нет в 1D),
  d+1: акустика плюс [1, u_bar+c_bar*n, H_bar+c_bar*(u_bar dot n)].
  u_bar=(sqrt(rho_L)*u_L+sqrt(rho_R)*u_R)/(sqrt(rho_L)+sqrt(rho_R)),
  H_bar=(sqrt(rho_L)*H_L+sqrt(rho_R)*H_R)/(sqrt(rho_L)+sqrt(rho_R)),
  H=(E+p)/rho, c_bar^2=(gamma-1)*(H_bar-|u_bar|^2/2).
В 2D t=(-n_y,n_x). В 3D выбирается декартова ось с наименьшим |direction_k|;
при равенстве первая в порядке x,y,z. Ее проекция на плоскость, нормальную n,
нормируется в t1, затем t2=n cross t1. Выбор оси использует исходное направление,
чтобы округление нормировки CPU/CUDA не меняло базис на почти равных компонентах.

EulerRoeBasis::right имеет фиксированный шаг строки 5, R(r,c)=right[5*r+c].
Активна матрица (d+2)x(d+2); остальные элементы нулевые.
characteristic_to_conservative выполняет только линейное умножение R*W:
его можно применять также к приращениям, которые не являются физическими
состояниями. Проверки rho>0 и p>0 выполняет затем выбранный солвер.
conservative_to_characteristic(frozen, direction, gamma, U, W) вычисляет
W = R^{-1} U на CPU и CUDA. Передавайте направление и gamma от построения
frozen. Функция также применима к скачку U_R - U_L и используется в потоке Роу.

CPU/CUDA
--------
Общие функции без выделения памяти:
  aero::EulerStatus s = aero::roe_conservative(
      d, U_L_ptr, U_R_ptr, direction_ptr, gamma, result_ptr);
  s = aero::roe_fluxes(d, F_L_ptr, F_R_ptr, U_L_ptr, U_R_ptr,
                      direction_ptr, gamma, result_ptr);
  s = aero::characteristic_to_conservative(basis, W_ptr, U_ptr);
Для ЛФ аналогичные указательные перегрузки.
Вызовы из CUDA выполняются внутри ядра верхнего уровня; все указатели должны
быть доступны в его памяти. Рабочий пример -- one_interface в
eulersolver_cuda_tests.cu: переход вынесен в вызывающее ядро, затем выбирается
ЛФ либо Роу. Производственный модуль сам ядра и обход сетки не запускает.
При AERO_EULERSOLVER_KERNEL_ONLY заголовки не подключают host STL.

CPU-перегрузки проверяют размеры std::vector и бросают исключения.
Общие функции возвращают EulerStatus. При ошибке результат не изменяется.
Требуются конечные числа, gamma>1, rho>0, p>0. Недопустимые состояния и
переполнение отклоняются, без скрытого подрезания плотности/давления.
Очень высокие числа Маха могут приводить к потере внутренней энергии при вычитании.
Длины сырых массивов и доступность памяти обеспечивает вызывающий.
Функции реентерабельны; OpenMP и CUDA-параллелизм организует верхний уровень.
CPU-сборка не зависит от CUDA; при отсутствии GPU вычисления можно выполнять на CPU.

Сборка
------
  make eulersolver-test
  make eulersolver-debug-test
  make eulersolver-test WITH_OPENMP=0
  make eulersolver-cuda-test
  make test

В msvs/aero.sln проекты aero_eulersolver и eulersolver_tests.
  MSBuild msvs\aero.sln /t:eulersolver_tests /p:Configuration=Release /p:Platform=x64 /p:WithCuda=true /p:RunEulersolverTests=true /p:RequireCudaTests=true
Для Debug заменить Configuration, для CPU -- WithCuda=false.
В MSYS2 выполните make eulersolver-cuda-test для проверки g++ и CUDA.
Из нативного mingw32-make доступна сборка через MSBuild:
  mingw32-make eulersolver-cuda-test MSBUILD="полный путь к MSBuild.exe" MSBUILD_CUDA_FLAGS="..."
В текущей конфигурации CUDA 12.3 используется ранее установленный явный обход:
  /p:VCToolsVersion=14.44.35207 /p:AllowUnsupportedCudaHostCompiler=true
По умолчанию обход выключен. Строгий C++11 проверяется GCC; MSVC использует
минимальный режим stdcpp14, nvcc предупреждает об игнорировании -std=c++11.
Успех тестов не означает официальной поддержки этой пары компиляторов.
Linux-ветка Make добавлена, но в Windows-сессии не проверялась.
Для исключения модуля из Make удаляется include source/eulersolver/eulersolver.mk.

Тесты
-----
Сохранены проверки ЛФ, базиса A*R=R*Lambda, направлений и ошибок.
Добавлены независимая проверка Роу через решение R*a=deltaU в тестах,
известный поток Сода, стационарные контакт/сдвиг/скачок, сверхзвуковой
односторонний поток, точность на совпадающих состояниях, смена ориентации,
готовые потоки, внешний переход состояний/приращений и скорость волн Роу.
На обеих GPU проверяются оба солвера, внешний переход, размерности 1/2/3,
разные gamma и направления, включая почти равные компоненты, а также ошибки
без записи за пределы одного результата. CUDA-тесты используют отдельный stream.
