Явное интегрирование по времени
===============================

Модуль source/explicit решает систему для неподвижных контрольных объёмов
V_i dU_i/dt = -R_i(t,U). Положительный R_i означает суммарный поток наружу.
Один вызов step выполняет один шаг для всех расчётных узлов и всех компонент.

Схемы
-----

explicit_euler.cpp задаёт явный Эйлер, ssprk3.cpp — трёхстадийную схему
SSPRK(3,3) Шу–Ошера. Для E(t,Y) = Y - dt R(t,Y)/V получаем

  Euler:   U_next = E(t,U)
  SSPRK3:  Y1     = E(t,U)
           Y2     = 3/4 U + 1/4 E(t+dt,Y1)
           U_next = 1/3 U + 2/3 E(t+dt/2,Y2).

Сборщик невязки вызывается один раз для Эйлера, три раза для SSPRK3. Указатель
values каждый раз содержит поле текущей стадии. Граничные данные, зависящие
от времени, вычисляют в момент, переданный сборщику. Общая функция обновления
одной компоненты находится в explicit_stage.h, обход поля на CPU — в explicit.cpp,
на GPU — в explicit_cuda.cu.

Общий для однопроцессного и MPI-решателя порядок стадий задаёт advance_stages
в stage_sequence.h. Если первая невязка уже собрана при выборе CFL, её
можно передать пятым аргументом step. Буфер содержит nodes*components
значений на выбранном устройстве и остаётся доступным до окончания вызова.
Тогда для Эйлера дополнительных вызовов сборщика нет, а для SSPRK3
сборщик вызывается в моменты t+dt и t+dt/2.

Пример C++11
------------

  #include "source/explicit/explicit.h"

  // grid — CvView или PeriodicView на CPU; U0 имеет node_count*components чисел.
  aero::ExplicitIntegrator integrator(grid.node_count, components, grid.volumes,
                                      U0.data(), aero::ExplicitBackend::Cpu);
  // assemble имеет сигнатуру:
  // void assemble(double stage_time, const aero::ExplicitField& field, double* R);
  integrator.step(aero::ExplicitScheme::SSPRK3, t, dt, assemble);
  t += dt;
  std::vector<double> output = integrator.state();

Создайте integrator один раз для всей серии шагов. Он копирует с CPU начальное
поле и положительные объёмы, выделяет рабочие массивы и владеет текущим
состоянием. Поле хранится подряд в порядке [узел][компонента]. При периодике
берутся объединённые объёмы и одно U0 на расчётный узел. Для вывода на исходную
сетку используйте отображение PeriodicView::node_dof.

Контракт сборщика невязки
-------------------------

Сборщик полностью перезаписывает R. Если внутри него вклады рёбер и границ
прибавляются к R, сначала обнулите его. Каждая компонента R содержит интегральный
поток: для внутренних рёбер учитывается площадь, а boundary_flux уже включает её.
Деление на V, знак минус и умножение на dt выполняет интегратор. На новой стадии
сборщик заново вычисляет реконструкции и потоки по field.values. Исходные данные
для base_* initial хранятся у вызывающего кода отдельно от поля стадии.

Верхний уровень выбирает положительный dt по своему критерию устойчивости
и обновляет t после успешного шага. Если сборщик выбросил исключение или
получилась нечисловая либо бесконечная компонента, последнее принятое U
сохраняется. Сборщик может отклонить и физически недопустимое состояние.
Один экземпляр интегратора используется последовательно.

CPU, OpenMP и CUDA
------------------

Auto выбирает доступный CUDA-бэкенд; в CPU-сборке или без устройства работает
на CPU. Для сборщика, реализованного только на CPU, укажите ExplicitBackend::Cpu.
Явный выбор Cuda требует доступного устройства; номер GPU задаётся последним
аргументом конструктора и по умолчанию равен нулю.

Сборщик вызывается на хосте. В режиме Cpu массивы доступны процессору, а
обновление больших полей допускает OpenMP. В режиме Cuda field.values,
field.volumes и R указывают на память field.device; сборщик запускает ядра
в cudaStream_t, полученном из field.stream. Выполняйте операции сборщика на
выбранном устройстве и завершайте работу других потоков до передачи управления.
Указатели полей стадии заимствуются на время вызова. Поля остаются на GPU
между шагами. Проверка стадии возвращает на CPU один признак ошибки; state()
копирует всё принятое поле и предназначен, например, для записи результата.

Сборка и тесты
--------------

  make explicit
  make explicit-test
  make explicit-debug-test
  make explicit-cuda-test

CPU-сборка использует C++11. WITH_OPENMP=0 отключает OpenMP.
Проекты MSVS: aero_explicit и explicit_tests. Для тестов с обязательным запуском
на GPU: Configuration=Release, Platform=x64, WithCuda=true, RequireCudaTests=true.
Для установленной связки CUDA 12.3 и MSVC 14.44 используются параметры
VCToolsVersion=14.44.35207 и AllowUnsupportedCudaHostCompiler=true.

Тест порядка использует U'=U+t, U(0)=1 с точным решением 2 exp(t)-t-1.
Тест переноса на неравномерной периодической линии проверяет каждую компоненту
и сохранение суммы V_i U_i. Тесты ошибок отклоняют промежуточную стадию и
повторяют шаг с последнего принятого состояния.
