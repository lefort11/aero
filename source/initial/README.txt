Начальные условия для уравнений Эйлера
====================================

Модуль один раз подготавливает U0 для принятой сетки, расчётной размерности
d=1,2,3 и gamma>1. Результат — std::vector<double> в порядке
[расчётный узел][rho, rho_ux, (rho_uy), (rho_uz), E]. E — полная энергия
на единицу объёма. Массив передаётся в ExplicitIntegrator на CPU или CUDA.
Формулы и файлы обрабатываются на CPU.

Формулы
-------

Пример блока для задачи Сода в 1D:

  initial_type formula
  rho = if(x < 0.5, 1, 0.125)
  ux  = 0
  p   = if(x < 0.5, 1, 0.1)

В 2D дополнительно задаётся uy, в 3D — uy и uz. Все компоненты соответствующей
размерности обязательны. Координаты x,y,z берутся из MeshData без применения
length_scale_to_meters. Каждое выражение независимо и вычисляется по координатам.
Например, в 2D можно задать ux = sin(2*pi*y), uy = 0.
При сборке U0 выполняется E = p/(gamma-1) + rho*|u|^2/2.

Парсер source/io/expression.h поддерживает десятичные числа с точкой,
экспоненциальную запись, переменные x,y,z, константу pi, скобки и операции:
  ^                      степень, справа налево; -2^2 равно -4
  + -                    унарный знак
  * /                    умножение и деление
  + -                    сложение и вычитание
  < <= > >= == !=        сравнения, дают 0 или 1
Функции: sin, cos (радианы), exp, sqrt, abs и if(условие, значение1, значение2).
Ненулевое условие выбирает первую ветвь. Выполняется только выбранная ветвь,
поэтому допустимо if(x == 0, 1, sin(x)/x). Деление на ноль и нечисловое
значение в вычисляемой ветви диагностируются с именем величины и номером узла.
Выражения разбираются один раз при чтении блока; допускаются строки формулы
до 65536 байт и вложенность разбора до 64 уровней.

Файл полей
----------

Вариант с одним консервативным полем:

  initial_type file
  path  "results/step 100.fields"
  field U

U — имя узлового поля. Имена компонентов такие же, как в описании U0 выше,
с учётом размерности. Порядок компонент внутри файла произвольный. Модуль
находит их по именам и преобразует компонентное хранение файла в узловое
хранение интегратора.

Вариант с примитивными полями для 2D:

  initial_type file
  path "results/initial.fields"
  rho = density
  ux  = velocity x
  uy  = velocity y
  p   = pressure

Справа указывается имя поля и, при необходимости, имя компоненты. Для
многокомпонентного поля выбор компоненты обязателен. Например, для имени
с пробелом можно написать ux = "gas velocity" x. Считываются только поля
NODE. Все величины и имена чувствительны к регистру. Ключ field и
сопоставления примитивных полей задают два взаимоисключающих способа чтения.

FieldSnapshot::read определяет текст, бинарный формат и LZMA по сигнатуре.
Проверяются сетка и её SHA-256, состав поля и физическая допустимость U.
Снимок даёт значения U0. Новый расчёт начинается с шага 0 при t = 0.
На нескольких CPU-процессах нужны глобальный снимок и .mdec версии 4.
Каждый процесс выбирает узлы своей части по исходным номерам.
Для продолжения с сохранённого шага запустите aero с флагом --recover
(см. source/aero/README.txt).

Подключение
-----------

  #include "source/initial/initial.h"
  #include "source/explicit/explicit.h"

  auto U0 = aero::read_initial_file(mesh, gamma, "case/initial.cfg");
  auto cv = dual.view();
  aero::ExplicitIntegrator solver(cv.node_count, mesh.data().dimension + 2,
                                  cv.volumes, U0.data());

Весь файл initial.cfg в примере содержит один блок. Для общего парсера
есть read_initial(mesh, gamma, input_stream, directory, periodic_view).
read_initial_file ищет относительный путь к снимку от каталога initial.cfg.
При вызове read_initial базовым каталогом служит аргумент directory.
В двойных кавычках пробелы, # и обратные косые черты входят в путь буквально.
Вне кавычек # начинает комментарий до конца строки.

Для периодической сетки:

  auto grid = domain.view();
  auto U0 = aero::read_initial_file(mesh, gamma, "case/initial.cfg", &grid);
  aero::ExplicitIntegrator solver(grid.node_count, mesh.data().dimension + 2,
                                  grid.volumes, U0.data());

Формулы и файлы интерпретируются по исходным узлам сетки. Для связанных
узлов проверяются все консервативные компоненты:
  |a-b| <= 1e-13 + 1e-10 * max(|a|, |b|).
При совпадении берётся значение первого исходного узла группы. Ошибка
содержит оба номера исходных узлов. Передаваемый PeriodicView должен
относиться к той же сетке и ссылаться на память CPU.

Сборка и проверка
-----------------

  make initial
  make initial-test
  make initial-debug-test

MSVS: aero_initial и initial_tests, решение msvs/aero.sln.
Тесты проверяют условные формулы и приоритет операций, начальные поля
в 1D/2D/3D, периодический шов, все три кодировки снимка, порядок компонент
и отказ при несовпадающей сетке или физически недопустимом состоянии.
