Шаг по числу Куранта
====================

Солвер aero по умолчанию использует cfl_method = height из main.txt.
Для каждого узла заранее известна наименьшая высота h примыкающих ячеек.
Шаг по конвекции равен CFL*h/(|u|+c); для Linear скорость и скорость звука
берутся из фона. В вязком расчёте к (|u|+c)/h добавляется вязкая оценка
в единицах обратного времени. При включённом SA учитывается также его шаг.
Один и тот же расчёт узла в residual/flux_cfl.h обслуживает CPU, GPU и MPI.

При local_time_step = auto узел сравнивает изменение плотности, давления,
скорости и рабочей вязкости с целями из implicit.txt. Параметры
local_time_step_density_change, local_time_step_pressure_change,
local_time_step_velocity_change и local_time_step_sa_change по умолчанию
равны 0.01, 0.01, 0.01 и 0.05. Множитель адаптации ограничивают
local_time_step_min_factor (0.5) и local_time_step_max_factor (1.25).

При cfl_method = spectral солвер использует приведённую ниже сумму по площадкам.
Библиотечный интерфейс CflTimestep принимает скорости на площадках и
вычисляет по ним один положительный dt для всей неподвижной сетки
Эйлера по текущим оценкам скоростей волн. Приграничные и внутренние узлы
участвуют в одном минимуме. CflStep содержит dt и номер ограничивающего
расчётного узла node. При равенстве выбирается меньший номер.

Формула
-------

  sigma_i = sum_f max_wave_speed[f] * |S_f|
  dt_i    = 2 * CFL * V_i / sigma_i
  dt      = min_i dt_i

S_f — вектор ориентированной площади из cv. Используется длина вектора
после суммирования геометрических вкладов. Скорость передаётся на единицу
площади даже для boundary_flux, который уже интегрирует сам поток.
Множитель 2 задаёт принятое определение CFL. На равномерной периодической
1D-сетке с постоянным состоянием dt = CFL * dx / (|u|+c). Допустимое число
Куранта выбирается для конкретной реконструкции, потока и интегратора.

Подготовка
----------

  #include "source/timestep/timestep.h"

  aero::CflTimestep plan(mesh.view(), dual.view());     // CPU, обычная сетка
  // или: aero::CflTimestep plan(domain.view(), device); // периодическая сетка

Конструктор один раз копирует геометрию с CPU и готовит CSR «узел — площадки».
Оригинальная сетка после подготовки модулю не нужна. Внутреннее ребро даёт
по одному вкладу каждому концу; физическая площадка даёт один вклад её узлу.
На периодической сетке используются только рёбра, внешние площадки и объёмы
PeriodicDomain. У петли обе стороны принадлежат одному узлу и дают два вклада.

device = -1 выбирает CPU, device >= 0 задаёт номер GPU. Для CPU-сборки CUDA
не требуется. В CUDA-варианте геометрия и рабочая память редукции выделяются
один раз. Два одновременных вычисления на GPU требуют отдельных экземпляров.

Один шаг расчёта
----------------

Для принятого поля U^n получите в ходе вычисления потоков max_wave_speed
из EulerFluxResult для каждого ребра (ЛФ или Роу) и каждой физической
площадки (boundary_flux). Передайте два массива в порядке геометрии:

  aero::WaveSpeeds speeds = {edge_speed, edge_count, boundary_speed, boundary_count};
  aero::CflStep limit = plan.compute(cfl, speeds);
  integrator.step(aero::ExplicitScheme::SSPRK3, t, limit.dt, assemble);
  t += limit.dt;

edge_speed и boundary_speed — указатели на double. При нулевой длине массива
допустим nullptr. На каждой новой принятой конфигурации поля скорости
обновляются. Внутри одного шага SSPRK3 используется один и тот же dt.
Для записи в заданный момент верхний уровень может уменьшить полученный dt.

Доступ к принятому полю без копирования
---------------------------------------

  aero::CflStep limit;
  integrator.inspect([&](const aero::ExplicitField& f) {
      // Сборщик приложения заполняет массивы по полю f.values.
      aero::WaveSpeeds speeds = evaluate_wave_speeds(f);
      limit = plan.compute(cfl, speeds, f.stream);
  });

Здесь evaluate_wave_speeds — функция приложения, использующая выбранные
реконструкцию, поток и граничные условия. При CUDA plan и массивы скоростей
должны находиться на устройстве f.device, запись скоростей планируется
в f.stream. Тогда минимум вычисляется на GPU, а на CPU возвращается только
пара (dt, node). inspect предоставляет поле только на время вызова,
активирует нужное устройство и дожидается работы своего потока. Его вызывают
между принятыми шагами. Только чтение поля разрешено и на CPU, и на CUDA.

Диагностика и проверки
----------------------

CFL и объёмы должны быть положительными и конечными. Скорости волн должны
быть конечными и неотрицательными. Узел с нулевой суммой скоростей не
ограничивает шаг. Если конечного шага нет ни у одного узла, compute сообщает
об ошибке. Некорректная геометрия, размер массива и нечисловые скорости
также диагностируются исключениями.

  make timestep
  make timestep-test
  make timestep-debug-test
  make timestep-cuda-test

Проект timestep_tests в msvs/aero.sln вызывает GNU Make. Для GPU укажите /p:KokkosBackend=cuda. Команда make timestep-cuda-test требует хотя бы одну доступную видеокарту.

Тесты охватывают равномерную и неравномерную линию, физические границы,
объединённые периодические узлы, ребро-петлю, длину наклонного вектора
площади, совпадающие минимумы и ошибки данных. Интеграционный тест получает
скорость волны от потока ЛФ для принятого поля до и после явного шага.

Функция minimum_step в cfl_detail.h сравнивает шаг и номер узла как одну пару.
Для небольших хостовых задач та же операция последовательно обновляет локальный минимум,
для больших задач и GPU выполняется редукция Kokkos.

Общий фильтр нелинейных поправок
--------------------------------
correction_filter.h содержит критерий медленного снижения полной невязки и веса
двух последовательных поправок. Эту формулу используют неявный перенос SA
и, при solver_damp_correction=on, предиктор и Ньютон газового решателя.
Фильтр не владеет полем или историей. Буферы остаются у интегратора.
