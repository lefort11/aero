Сетка
=====

aero::Mesh хранит узлы, грани, элементы и имена границ. Элемент задаётся
через общие грани. Одна и та же структура подходит для неравномерных
отрезков в 1D, полигонов в 2D и многогранников в 3D. Тетраэдры, призмы
и гексаэдры могут соседствовать в одной сетке. Интерфейс объявлен в mesh.h.

Чтение, обход и запись
----------------------

Пример на C++11 читает сетку из каталога примеров, печатает пары узлов
для рёбер первой грани первого элемента и сохраняет сжатую копию.
Пути отсчитываются от корня проекта.

  #include "source/mesh/mesh.h"
  #include <iostream>

  int main() {
      aero::Mesh mesh = aero::Mesh::read("examples/tecplot/demo_3d.mesh");
      const auto cell = mesh.cell(0);
      const auto face = cell.face(0);
      std::cout << "Face " << face.id() << ", edges " << face.edge_count() << '\n';
      for (auto id : face.edge_ids()) {
          const auto edge = mesh.edge(id);
          std::cout << id << "  " << edge.node_id(0) << "  " << edge.node_id(1) << '\n';
      }
      mesh.write("copy.mesh", aero::MeshFormat::Lzma);
  }

В mesh.edge(id) аргумент — номер ребра во всей сетке. В cell.face(k)
и face.edge(k) аргумент — позиция внутри элемента или грани. Метод id()
возвращает номер сущности в сетке. У ячейки также есть node_ids(), edge_ids()
и face_ids(). Списки узлов и рёбер ячейки отсортированы по номеру.
Для обхода контура 3D-грани используйте face.node_ids(). Концы каждого
ребра упорядочены по возрастанию номера узла.

Топология в памяти
------------------

MeshData хранит координаты в трёх массивах double одинаковой длины
x, y, z при любой размерности. node.x(), node.y(), node.z() возвращают
значения из файла. Все геометрические операции используют эти координаты напрямую.

Две основные таблицы CSR — face_nodes (грань → узлы) и cell_faces
(элемент → грани). Строка i занимает позиции от offsets[i] включительно
до offsets[i+1] исключительно в массиве indices. Нумерация начинается
с нуля, MeshIndex — беззнаковое 64-битное целое. На каждую запись
cell_faces.indices приходится один знак в cell_face_orientation.

  1D  Грань — узел. У отрезка две грани со знаками −1 в начале и +1
      в конце. У элемента одно ребро, у каждой точечной грани — ноль.
  2D  Грань — направленная пара узлов, ей соответствует одно ребро.
      Знак +1 сохраняет направление при обходе контура ячейки, −1
      разворачивает его. Допустим один замкнутый контур, в том числе вогнутый.
  3D  Грань — циклический список узлов многоугольника. Знак +1 использует
      этот порядок как наружную ориентацию ячейки, −1 разворачивает его.
      Грани элемента образуют связную замкнутую ориентированную оболочку.

При создании Mesh из MeshData или при чтении строятся общая таблица рёбер
и связи грань → рёбра, элемент → узлы, элемент → рёбра. Чтобы задать сетку
из кода, заполните MeshData и передайте его конструктору Mesh.

Граничные метки
---------------

Каждая внешняя грань встречается в boundary_faces один раз. Для записи k
номер грани равен boundary_faces[k], а имя границы доступно как
patch_names[boundary_patch[k]]. Внутреннюю грань используют две ячейки
с противоположными знаками. Имена границ, например "wing", хранятся
в сетке. Типы условий и пары периодических границ задаются в bc.txt.

Формат файла v3
---------------

Mesh::read распознаёт кодировку по сигнатуре независимо от расширения.
Mesh::write принимает MeshFormat::Text, Binary (по умолчанию) или Lzma.
Для работы с потоками есть перегрузки read(std::istream&) и write(std::ostream&, ...).

Пример текстового файла — два отрезка длиной 0.25 и 0.75 с общей гранью 1.
Внешние грани 0 и 2 имеют метки "left" и "right".

AEROMESH 3 TEXT
DIMENSION 1
COUNTS 3 3 3 2 4 2 2
X 0 0.25 1
Y 0 0 0
Z 0 0 0
FACE_OFFSETS 0 1 2 3
FACE_NODES 0 1 2
CELL_OFFSETS 0 2 4
CELL_FACES 0 1 1 2
CELL_ORIENTATIONS -1 +1 -1 +1
BOUNDARY_FACES 0 2
BOUNDARY_PATCH 0 1
PATCH_NAMES "left" "right"
END

Семь чисел COUNTS по порядку означают число узлов, граней, записей
FACE_NODES, элементов, записей CELL_FACES, внешних граней и меток.
Имена меток — уникальные непустые строки UTF-8 в двойных кавычках.

Бинарный файл начинается с восьми байтов AEROMSHB и номера версии 3
(uint64). Далее идут значения в том же порядке, что в тексте, без названий
секций и END. Порядок байтов little-endian. Целые занимают 8 байт, знак
ориентации — 1 байт (0x01 или 0xff), координаты — IEEE-754 binary64.
Перед каждым именем записана его длина в байтах. Вариант Lzma упаковывает
бинарный v3 в контейнер AEROLZMA из модуля io (см. ../io/README.txt).
Поддерживается также чтение v2 во всех трёх кодировках. Старое поле
LENGTH_SCALE_TO_METERS пропускается при расчёте геометрии.

Представление для CPU и CUDA
----------------------------

Mesh владеет массивами на CPU. mesh.view() возвращает MeshView с размерами
и указателями. Методы node(), edge(), face(), cell() и доступ к связности
доступны в коде CPU и CUDA. Для запуска ядра по такому представлению
массивы должны находиться в доступной GPU памяти, а указатели в переданном
MeshView должны указывать на эти массивы. Имена меток доступны на CPU.
Представление и полученные из него объекты действительны, пока существует
соответствующее хранилище. Mesh проверяет номера в своих методах доступа,
а в MeshView и во вложенных обращениях корректность индексов обеспечивает
вызывающий код.

Распределённая сетка
--------------------

Для архива .mdec используется load_partition(path, world) из partition.h.
Результат MeshPartition содержит локальную Mesh, соответствие локальных
номеров узлов, граней и элементов глобальным (nodes, faces, cells) и ранги
владельцев узлов (node_owners). Архив готовит утилита meshdec. Пример
подготовки и запуска приведён в ../../utils/meshdec/README.txt.

Для общего вывода визуализации read_archive_geometry восстанавливает геометрию
на одном ранге. Первый проход по листьям заполняет координаты, длины строк
и таблицу исходных номеров. Второй проход заполняет связность. В каждый момент
распакован один лист. Временная таблица освобождается перед построением Mesh.

Проверки
--------

Конструктор Mesh(MeshData) и Mesh::read проверяют CSR, диапазоны индексов,
ориентации, полноту границ, конечность координат.
Для проверки существующей сетки есть mesh.validate(). Ошибки формата
и топологии сообщаются через MeshError. Проверка плоскостности, пересечений
и положительности геометрических объёмов выходит за рамки Mesh::validate().
При чтении MeshReadLimits по умолчанию ограничивает исходные массивы и строки
одним ГиБ, а отдельное имя — 4096 байт. Производные связи требуют дополнительной памяти.

Из корня проекта make test запускает в том числе mesh_tests.cpp. Команда
make cuda-check проверяет компиляцию доступа к сетке из CUDA-ядра.

Тесты сетки используют tests/mesh_fixture.h. Ориентация граней, нумерация и геометрия
генераторов совпадают с теми, по которым модуль CV проверяет контрольные объёмы.
