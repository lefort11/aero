Пространственная невязка уравнений Эйлера
========================================

SpatialResidual собирает сумму выходящих интегральных потоков R. Интегратор
использует dU/dt = -R/V. U и неизменное начальное U0 имеют порядок [узел][d+2].
Геометрия, правила границ и шаблон копируются при подготовке. При каждом вызове
состояния берутся из текущей стадии интегратора.

  auto options = aero::residual_options(run.reconstruction_variables,
                                        run.euler_solver, run.gamma);
  aero::SpatialResidual op(mesh.view(), dual.view(), std::move(stencil),
                           boundaries.by_patch, options, device);
  op.assemble(U, U0, R, edge_speeds, boundary_speeds, stream);

Для периодики используйте конструктор с размерностью и domain.view(), а шаблон
получите через domain.prepare(...). Поля задаются в компактной нумерации domain.
Обе стороны петли входят в сумму узла с противоположными знаками. Граничные
площадки берутся только с физических границ.

Основной обход идёт по рёбрам. Реконструкция использует геометрический шаблон
вдоль ребра. Физические потоки и базис Роу используют нормаль к дуальной грани.
Вектор площади ориентирован от begin к end. Поток вычисляется один раз,
умножается на площадь и сохраняется. Граничный поток уже интегрален.
Затем каждый узел собирает свои знаковые вклады по CSR в фиксированном порядке.
Скорости для CflTimestep остаются скоростями на единицу площади.

В main.txt reconstruction выбирает схему, reconstruction_variables — величину.

  conservative      U_L = U_i + delta2_L/2, U_R = U_j - delta2_R/2.
  characteristic    На ребре строится один базис Роу по U_i и U_j. Все узлы
                    обоих шаблонов проецируются через W = R_roe^-1 U. После
                    реконструкции R_roe переводит приращения W обратно в U.
  flux              По одной нормали реконструируются физические потоки F_n.
                    Для скачка и скорости волн отдельно реконструируются U_L/U_R.

В каждом режиме доступны roe и lf. gamma для всех операций берётся из gas.txt.
Перед решателем Римана Aero проверяет реконструированные состояния с каждой
стороны ребра. При выходе плотности или давления
за абсолютные границы [1e-16, 1e16] подставляется состояние своего узла.
Затем trace_ratio_min и trace_ratio_max ограничивают относительное изменение
плотности и давления. Один коэффициент линейно смешивает узловые и
реконструированные плотность, скорость и давление, после чего пересчитывается
полная энергия. В режиме flux тот же коэффициент ограничивает приращение
потока от узлового значения. Недопустимый поток прерывает сборку с номером
ребра или граничной площадки.
Если хотя бы один конец ребра лежит на входе или выходе (free, superin,
superout), поток на ребре вычисляется по текущим состояниям обоих узлов.
Это правило действует при любом шаблоне реконструкции. Поток через внешнюю
грань задаётся её граничным условием. На периодическом шве шаблон включает
узлы из соседнего периода.
При исключении результаты вызова нужно отбросить.

Метод assemble_cfl собирает невязку и определяет шаг CFL по тем же
потокам и спискам граней. Массив объёмов берётся из интегратора на выбранном
устройстве. Для остальных стадий SSPRK3 используется assemble_rhs.
Вызов assemble по-прежнему выдаёт скорости на рёбрах и граничных площадках.

Размеры выходных массивов: nodes*(d+2), edges и boundary_count. Снимок U0 нужен,
когда активное граничное правило обращается к initial. Для вложенной в 3D
прямой или плоскости передайте ResidualFrame с ортонормированными осями,
вдоль которых заданы компоненты импульса. По умолчанию используются x, y, z.

device = -1 выбирает CPU. Для GPU передайте номер устройства и указатели на
его память. stream задаёт поток CUDA. Ошибки проверяются до возврата из вызова.
Один экземпляр рассчитан на последовательные вызовы. Независимые одновременные
сборки используют разные экземпляры.

Проверка: make residual-test, make residual-debug-test, make residual-cuda-test.
В Visual Studio используйте residual_tests, WithCuda=true и RequireCudaTests=true
для обязательного прогона на GPU. Параметры установленной связки nvcc и MSVC
описаны в ../reconstruction/README.txt.
