Граничные условия для уравнений Эйлера
=====================================

Модуль работает на неподвижной сетке в 1D/2D/3D для идеального газа, gamma > 1.
bc.cpp читает блок настроек на CPU. bc.h вычисляет поток одной физической
площадки по общей формуле CPU/CUDA. Для периодических пар periodic.cpp строит
расчётную связность, а periodic_stencil.cpp готовит шаблоны реконструкции.
Настройки относятся к расчёту. Файл сетки содержит только имена меток.

Стенка и открытая граница
------------------------

Блок применяется к метке, выбранной вызывающим кодом. Примеры отдельных блоков:

  bc_type wall

  bc_type free
  superin initial
  inflow  base_p initial
  outflow base_u 20

На неподвижной стенке возвращается поток (0, p_i S, 0), где S — наружный
вектор площадки. Газ может скользить по стенке.

Для free обязательны три строки. При каждом вычислении потока free_boundary_state
в bc.h берёт текущее внутреннее состояние, наружную нормаль n = S/|S|,
нормальную скорость u_n = dot(u_i, n) и местную скорость звука c.

  u_n <= -c       superin   — полное состояние сверхзвукового входа
  -c < u_n < 0    inflow    — одно условие дозвукового входа
  0 <= u_n < c    outflow   — одно условие дозвукового выхода
  u_n >= c                  — поток внутреннего газа, все волны уходят

Одна и та же метка может одновременно иметь площадки с разными режимами.
base_p означает статическое давление, base_u — нормальную скорость со знаком,
base_rho — плотность. Правило без аргумента берёт значение из текущего
внутреннего состояния. initial берёт выбранную величину из состояния этой
площадки при t=0. Число задаёт постоянную в единицах полей расчёта.
Пустые строки и комментарии после # пропускаются.

При дозвуковом течении сохраняются внутренние касательная скорость,
K = p_i/rho_i^gamma и исходящий нормальный инвариант J+ = u_n + 2c_i/(gamma-1).
Для base_p: rho_b = (p_b/K)^(1/gamma); для base_rho: p_b = K rho_b^gamma.
Затем u_nb = J+ - 2c_b/(gamma-1). Для base_u сначала вычисляется
c_b = (gamma-1)(J+ - u_nb)/2. Если все данные текущие, получается поток
внутреннего состояния. На дозвуковом входе выбор K и касательной скорости
изнутри является принятым замыканием входящих энтропийной и сдвиговых волн.

Сверхзвуковой вход
------------------

В строке superin без аргументов основой служит текущее внутреннее состояние.
Слово initial выбирает начальное состояние этой площадки. Затем можно заменить
плотность, давление и отдельные компоненты скорости по размерности сетки.
Например, строка «superin initial rho=1.2 p=101325 ux=500» задаёт сверхзвуковой
вход при наружной нормали против оси x. После замен состояние должно по-прежнему
соответствовать сверхзвуковому входу. При другом режиме эта строка не читается
при вычислении потока. Файлы со старыми отдельными сверхзвуковыми метками
переводятся на bc_type free и три строки, показанные выше.

Вызов физического потока
------------------------

  aero::BoundaryPatches patches;
  auto bc = aero::read_boundary(settings, dimension, patches);
  double area[3] = {piece.area.x, piece.area.y, piece.area.z};
  aero::EulerFluxResult result;
  auto status = aero::boundary_flux(dimension, bc, patches.free_rules.data(), U, U_initial, area, gamma, &result);

BoundaryConfig хранит метку стенки, периодики или индекс открытой границы.
Три правила принадлежат FreeBoundaryRules. В patches.free_rules записи есть
только для открытых границ. При переносе на GPU таблица занимает память
пропорционально числу таких границ. Пары и их переносы хранятся отдельно.

U и U_initial имеют d+2 компоненты: плотность, d компонент импульса и полную
энергию на единицу объёма. Для наклонной 1D/2D сетки сначала выразите area
в базисе солвера. Начальные данные хранит вызывающий код; можно передать nullptr,
если активное правило их не требует. При Success result.flux уже включает площадь,
его добавляют к невязке данного узла. max_wave_speed задан без множителя площади.
При ошибке результат сохраняет прежнее значение. MissingInitial указывает на
отсутствующий начальный вектор, IncompatibleRegime — на несовместимость
характеристического режима, InvalidTarget — на недопустимое заданное значение.

Периодическая пара
------------------

  bc_type periodic
  patch bottom
  pair top
  translation 0 100 0

Один блок задаёт оба направления. Названия в этом синтаксисе — отдельные
токены. Вектор переноса идёт от bottom к top, три компоненты задаются для
любой размерности. Они выражены в исходных координатах сетки: если y_top
отличается от y_bottom на 100, укажите 100 независимо от length_scale_to_meters.
Две стороны должны совпасть по узлам и граням после переноса. Вращение,
интерполяция между несогласованными сетками и скачок полей здесь не заданы.

Пример подготовки (settings — поток одного блока, mesh уже загружена):

  #include "source/bc/periodic.h"

  aero::PeriodicPair pair;
  aero::BoundaryPatches patches;
  aero::read_boundary(settings, mesh.data().dimension, patches, pair);
  aero::PeriodicDomain domain(mesh, {pair});
  auto grid = domain.view();
  aero::ReconstructionOptions opts;
  opts.scheme = aero::ReconstructionScheme::Ebr5;
  auto stencil = domain.prepare(opts);

Для нескольких пар передайте один вектор всех пар. Mesh должна жить дольше
domain и сохранять исходную геометрию. Конструктор сверяет взаимно однозначное
соответствие узлов, связность граней и рёбер, противоположность наружных
площадок. По умолчанию допуск по координатам равен 1e-10 от длины самого
короткого заданного переноса. Третьим аргументом можно задать абсолютный
допуск в координатах сетки. Ошибки сопоставления сообщаются через MeshError.

grid.node_dof[n] задаёт расчётный номер исходного узла. Храните одно U на
расчётный номер; для вывода на исходную сетку берите U[grid.node_dof[n]].
volumes содержит суммарные узловые объёмы. Для каждого элемента grid.edges
будет один вызов внутреннего солвера. begin и end — расчётные номера,
area — ориентированный суммарный вектор, original — номер представительного
ребра исходной сетки. Строки stencil адресуются индексом в grid.edges.
Для физической части границы обходите только grid.boundary: поле node уже
содержит расчётный номер, face и patch остаются исходными. При периодике
по нескольким направлениям угловые узлы объединяются транзитивно.

При расчёте на нескольких CPU-процессах aero использует те же пары и переносы
из bc.txt. Сопоставление распределено по владельцам исходных вершин.
Пример конфигурации и формат распределённого вывода приведены
в ../aero/README.txt, раздел «Распределённый расчёт на CPU».

Шаблоны готовятся на временном продолжении сетки (один или два слоя).
Готовые веса обращаются к компактному полю по расчётным номерам; продолжение
можно освободить до начала расчёта. ReconstructionContext переносит шаблоны
на CUDA. Для PeriodicView верхний уровень копирует нужные массивы на устройство
и заменяет адреса в дескрипторе, как и для CvView.

Сборка и тесты
--------------

  make bc
  make bc-test
  make bc-debug-test
  make bc-cuda-test

MSVS: проекты aero_bc и bc_tests в msvs/aero.sln. Для CUDA задайте WithCuda=true,
для обязательного запуска тестов на GPU — RequireCudaTests=true. Настройка
совместимости nvcc и MSVC описана в ../eulersolver/README.txt.

bc_tests.cpp и bc_cuda_tests.cu проверяют физические потоки на CPU и GPU.
periodic_tests.cpp сравнивает реконструкции и невязку переноса на периодической
линии с явно продолженной сеткой, проверяет совмещение углов в 2D/3D и
диагностику несогласованных меток. CUDA-тест сверяет приращения на обеих
сторонах рёбер с тем же эталоном.
