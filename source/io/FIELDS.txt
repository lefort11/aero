AEROFIELDS v1: поля одного состояния расчета без сетки
=====================================================

Интерфейс: fields.h, реализация: fields.cpp.
Все размерности 1D/2D/3D используют одинаковый формат. В файле отсутствуют
координаты, связность, граничные грани и геометрия. Для визуализации требуется
отдельная сетка. Один файл соответствует одному сохраненному состоянию.

Пример C++11 (mesh -- уже загруженная aero::Mesh):

  #include "source/io/fields.h"
  #include "source/mesh/mesh.h"

  aero::FieldSnapshot snapshot(mesh, 100, 0.001); // шаг, время в секундах
  aero::Field pressure;
  pressure.name = "pressure";
  pressure.location = aero::FieldLocation::Cell;
  pressure.components = {"value"};
  pressure.units = "Pa";
  pressure.values.assign(static_cast<std::size_t>(mesh.view().cell_count), 101325.0);
  snapshot.fields.push_back(pressure);
  snapshot.write("build/result_000100.fields", aero::FieldFormat::Lzma);

  aero::FieldSnapshot loaded = aero::FieldSnapshot::read("build/result_000100.fields");
  loaded.check_mesh(mesh);

write/read также принимают std::ostream/std::istream. Чтение не требует seek
и определяет формат по сигнатуре, независимо от расширения. Запись по умолчанию
Binary. Другие варианты: Text и Lzma. Неверные данные выявляются до открытия
файла для записи; ошибка самого ввода-вывода может оставить частичный файл.
Пути используют узкую строковую кодировку платформы, как в модуле mesh.

Данные и связь с сеткой
----------------------
FieldSnapshot содержит:
  dimension     1, 2 или 3
  counts        количество NODE, EDGE, FACE, CELL, именно в таком порядке
  mesh_sha256   64 строчных шестнадцатеричных символа
  step          uint64 номер шага
  time          конечное double, физическое время в секундах
  fields        набор полей

Конструктор от Mesh заполняет размерность, количества и отпечаток. Конструктор
по умолчанию создает непривязанное состояние (dimension=0), которое нельзя
записать до заполнения метаданных. Можно хранить состояние без полей, а также
поля с нулем сущностей для пустой сетки.

mesh_sha256 = SHA-256 полного результата Mesh::write(..., MeshFormat::Binary),
то есть бинарного AEROMSHB версии 2, включая сигнатуру и все метаданные.
Хеш вычисляется потоково, без копии сериализованной сетки в памяти.
Он зависит от координат, связности, порядка/нумерации, ориентаций, масштаба
и имен границ. Производные массивы, которых нет в AEROMSHB v2, не хешируются.
Пересохранение той же сетки в Text/Binary/Lzma не меняет ее отпечаток.
При изменении самого формата сетки правило хеширования потребует явного
согласования версий. Формат v1 полей фиксирует именно AEROMSHB v2.

read() проверяет сам файл полей, но не соответствие сетке: сетка не нужна для
чтения. check_mesh(mesh) отдельно сравнивает размерность, все четыре количества
и отпечаток. Вызывать перед объединением сетки и полей. Нельзя использовать
поля с перенумерованной сеткой без соответствующего преобразования данных.

Field содержит name, location, components (имена компонент), units, values.
Привязки: Node, Edge, Face, Cell. Поле охватывает все сущности выбранного типа.
Пара (location, name) уникальна; одинаковое имя на узлах и элементах разрешено.
Имена полей и компонент непустые. Имена компонент уникальны внутри поля.
Единицы могут быть пустыми; строка не интерпретируется и значения не пересчитываются.
Все строки -- корректный UTF-8 без ASCII-управляющих символов и DEL.

Все значения float64. Хранение по компонентам:
  values[component * entity_count + entity_id]
Количество компонент произвольное, положительное, не привязано к размерности:
например, три компоненты скорости или девять компонент тензора в 2D допустимы.
Количество значений = counts[location] * components.size().
Сущности нумеруются от нуля в порядке сетки. Отдельного массива ID нет.
Списки только для части сущностей и поля только на граничных гранях v1 не хранит.

Конечные float64 сохраняются без потери точности во всех вариантах, включая
отрицательный ноль и субнормальные числа. В полях допустимы диагностические
nan, inf, -inf. В Text NaN нормализуется: знак и полезная нагрузка NaN не сохраняются;
Binary/Lzma хранят битовое представление double. Время обязано быть конечным.

Текстовый формат
----------------
  AEROFIELDS 1 TEXT
  DIMENSION 2
  MESH_SHA256 "<64 строчных hex-символа>"
  COUNTS 3 3 3 1
  STEP 100
  TIME 0.001
  FIELDS 1
  FIELD "pressure"
  LOCATION CELL
  COMPONENTS 1 "value"
  UNITS "Pa"
  VALUES 1
  DATA 101325
  END_FIELD
  END

Секции идут строго в приведенном порядке. FIELD..END_FIELD повторяется FIELDS
раз. VALUES -- число сущностей, а не полное число скалярных значений. DATA
содержит VALUES * COMPONENTS чисел по компонентам. Количество строк незначимо.
Пробельные символы разделяют токены. Комментарии не поддерживаются.
Строки в двойных кавычках; обратный слеш экранирует только кавычку и слеш.
Числа десятичные, точка независимо от локали; запись double с max_digits10.
После END допустимы только пробельные символы.

Бинарный формат (без выравнивания и служебных названий секций)
------------------------------------------------------------
Заголовок, ровно 112 байт:
  8 байт    ASCII "AEROFLDB"
  uint64    версия = 1
  uint64    размерность
  32 байта  SHA-256 (сырой digest, порядок как в hex-строке)
  4*uint64  counts: NODE, EDGE, FACE, CELL
  uint64    step
  float64   time
  uint64    число полей

Для каждого поля:
  string    name
  uint8     location: NODE=0, EDGE=1, FACE=2, CELL=3
  uint64    число компонент C
  C*string  имена компонент
  string    units
  uint64    число сущностей N (должно совпадать с counts[location])
  N*C*float64 values, по компонентам

Все целые little-endian. float64 -- IEEE-754 binary64 little-endian.
string = uint64 длина в байтах + UTF-8 байты, без завершающего NUL.
После последнего массива сразу EOF; хвостовые данные отклоняются.

LZMA и ограничения чтения
-------------------------
Lzma -- общий контейнер AEROLZMA v1 из aero_io, содержащий полный бинарный
AEROFLDB v1. Текст внутри LZMA и вложенные контейнеры не допускаются.
Блоки по 1 МиБ, CRC32, проверка размеров, свойств и конца блоков -- в aero_io.
Это не .xz, не .7z и не .lzma-alone. Подробности: source/io/README.txt.

FieldReadLimits (изменяемые поля структуры):
  max_payload_bytes  1 ГиБ: выделяемые массивы/строки, включая объекты Field
                     и string в массивах; без накладных расходов аллокатора,
                     фиксированного заголовка и рабочей памяти кодека
  max_decoded_bytes  2 ГиБ: полный распакованный файл, включая метаданные;
                     в Text включает пробелы, в Lzma -- вложенный Binary
  max_string_bytes   4096 байт на строку
  max_fields         1024
  max_components     1024 на поле

Проверяются переполнения произведений/счетчиков до выделения памяти, размеры
массивов, уникальность имен, размерность, время, UTF-8, версия и отсутствие
лишних данных. Ошибки файла/формата/сжатия сообщаются через aero::FieldError.
Ошибки в переданном объекте Mesh могут сообщаться через aero::MeshError.
Ограничения чтения не ограничивают создание/запись больших состояний;
при чтении таких файлов нужно явно увеличить соответствующие лимиты.

Сборка и тесты
--------------
  make io                   библиотека build/libaero_io.a
  make io-fields-test          тесты модуля
  make io-fields-debug-test    тесты с проверками стандартной библиотеки GCC
  make test / debug-test    все тесты проекта, включая тесты полей

Makefile собирает C++11. Для чтения и записи полей достаточно aero_io. Для привязки к сетке подключите также mesh.
MSVS: msvs/aero.sln, проекты aero_io и io_fields_tests, Debug/Release x64.
Тесты выполняются после сборки io_fields_tests. Для отключения: /p:RunOutputTests=false.
MSVC не имеет режима C++11; совместимость проверяется строгой сборкой GCC.
Ввод-вывод выполняется на CPU. Массивы на GPU нужно предварительно скопировать
в память CPU; модуль не требует CUDA и не управляет передачами GPU.

SHA-256 реализован по FIPS 180-4, раздел 6.2:
  https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf
Это идентификация сетки, не цифровая подпись и не аутентификация файла.
Тесты включают стандартные SHA-256 векторы, независимый бинарный пример,
все размерности/привязки/кодировки, несовпадения сеток, числа/UTF-8, ошибки
записи, усечение файлов, ограничения чтения и многоблочное сжатие.
