Общий модуль ввода-вывода aero_io (C++11, CPU)
=============================================

Интерфейсы модуля
  settings.h           Аргументы запуска, main.txt и cuda.txt.
  settings_boundary.h  Привязка секций bc.txt к меткам загруженной сетки.
  fields.h       Чтение и запись полей AEROFIELDS v1. Формат и примеры см. в FIELDS.txt.
  flowreport.h   Консольный отчёт по принятому шагу в 1D, 2D и 3D.
  output_settings.h   Именованные зоны и параметры записи из output.txt.
  scheduled_output.h  Расписание зон и запись выбранных узловых полей.
  lzma_stream.h  Блочное сжатие для сеток и файлов полей.
  expression.h   Разбор и вычисление формул от координат x, y, z.

Настройки расчёта
-----------------
Комплект в templates/ использует сетку examples/tecplot/demo_2d.mesh.
Интерфейс командной строки для основной программы:

  ./bin/aero --input=./templates --output=./results

Оба аргумента обязательны, порядок произвольный. Каталоги отсчитываются от
текущего каталога. Параметр --interactive включает паузу после вывода меток
сетки для редактирования и повторного чтения bc.txt.

В main.txt каждая строка имеет вид «ключ = значение». Все перечисленные ключи обязательны.
  mesh             Путь к файлу сетки. Относительный путь отсчитывается от --input.
  reconstruction   first_order, ebr3, ebr5, weno3 или weno5.
  reconstruction_variables   conservative, characteristic или flux.
  time_scheme      euler или ssprk3.
  cfl              Положительное конечное число.
  backend          cpu или cuda.
  euler_solver     roe или lf (локальный поток Русанова).
  final_time       Конечное время расчёта, число >= 0.

Дополнительные параметры trace_ratio_min и trace_ratio_max задают нижнюю и верхнюю
границы отношения реконструированной плотности и давления к узловым значениям.
Допустимы 0 <= trace_ratio_min < 1 < trace_ratio_max. По умолчанию границы равны
0 и 1e16. При выходе за относительную
границу один коэффициент ограничивает все примитивные переменные данной стороны.

Дополнительные целочисленные параметры main.txt
  omp_threads       Число потоков OpenMP на CPU. 0 или пропуск сохраняет настройки
                    среды выполнения (включая OMP_NUM_THREADS). Применяется после
                    успешного чтения настроек. В последовательной сборке работает один поток.
  flowreport_every  Интервал отчёта в принятых шагах. При 100 выводятся шаги
                    100, 200 и далее. 0 или пропуск отключает отчёт.

В gas.txt задаётся показатель адиабаты идеального газа, например gamma = 1.4.
Парсер требует конечное число больше 1. При переносе прежнего набора настроек
добавьте gas.txt и ключ reconstruction_variables в main.txt.

cuda.txt нужен только при backend = cuda. Пример строки: devices = 0,1.
Список сохраняет заданный порядок. Номера целые, от нуля, без повторов.
Доступность устройств определяет драйвер расчёта при запуске. Разбор файлов
можно выполнять на машине без CUDA.

init.txt задаёт начальное состояние. Синтаксис формул и загрузки снимка
описан в ../initial/README.txt. Путь к полям отсчитывается от каталога init.txt.
В шаблоне активна формула. Вариант с узловым полем U приведён в комментарии.

В bc.txt секция [имя] соответствует метке сетки. Внутри действуют правила
из ../bc/README.txt. В секции периодики задайте bc_type periodic, pair и
translation. Исходная сторона берётся из заголовка секции. Одно описание
покрывает обе метки. Каждая метка сетки должна встретиться ровно один раз.
Для имени или пути с символом # используйте двойные кавычки, например
["top #2"]. Вне кавычек # начинает комментарий.

Последовательность вызовов в основной программе:

  auto run = aero::read_run_settings(aero::parse_run_arguments(argc, argv));
  auto mesh = aero::Mesh::read(run.mesh_path);
  auto bc = aero::read_case_boundaries(run.boundary_path, mesh.data());

  // Для сетки с периодическими парами:
  aero::PeriodicDomain domain(mesh, bc.periodic_pairs);
  auto grid = domain.view();
  auto U0 = aero::read_initial_file(mesh, run.gamma, run.initial_path, &grid);

  // Для обычной сетки достаточно:
  auto U0_plain = aero::read_initial_file(mesh, run.gamma, run.initial_path);

Проверка всего комплекта: make io-settings-test или проект io_settings_tests
в Visual Studio. Тест читает файлы из templates, строит периодические связи
и вычисляет начальные значения в расчётных узлах.

Запись полей по зонам
---------------------
read_run_settings читает output.txt из каталога --input в run.output_zones.
Если файл отсутствует или пуст, список зон пуст. Заголовок секции задаёт имя
зоны вывода. В этой версии каждая зона охватывает всю исходную сетку.

  [latest]
  file = latest.fields
  every_steps = 100
  variables = rho, ux, uy, p, E
  multi = 0

  [pressure_history]
  file = pressure.fields
  every_time = 0.05
  variables = p
  multi = 1
  format = lzma

У каждой зоны своё расписание. Задайте один положительный интервал:
every_steps в принятых шагах или every_time в единицах расчётного времени.
Отсчёт начинается с нуля, первая запись выполняется через один интервал.
При совпадении сроков все соответствующие зоны получают один принятый снимок.
На конечном шаге применяются те же правила.

file задаёт имя относительно --output. Программа aero создаёт каталог назначения
и используемые подкаталоги при подготовке. При multi = 0 (по умолчанию)
готовый снимок заменяет предыдущий. При multi = 1 номер шага вставляется перед
последним расширением, например pressure_000037.fields. Номера длиннее шести
цифр записываются целиком. Существующий файл с этим номером вызывает ошибку.
Каждый файл публикуется после успешной записи в том же каталоге. При ошибке
очередной зоны повторите write с теми же шагом, временем и принятым состоянием.
Уже опубликованные на этом шаге зоны будут пропущены.

variables задаёт имена отдельных скалярных полей NODE в порядке записи.
Доступны rho (плотность), ux, uy, uz (компоненты скорости по размерности
сетки), p (давление) и E (плотность полной энергии). Давление вычисляется
с gamma из gas.txt. format задаёт формат AEROFIELDS: binary (по умолчанию),
text или lzma. Файл содержит номер шага, время и отпечаток исходной сетки.

Вызовы записи в цикле расчёта

  aero::ScheduledOutput output(run.output_zones, run.directories.output, mesh, run.gamma);
  // Перед каждым шагом candidate_dt уже ограничен по CFL и final_time.
  const double dt = output.limit_dt(time, candidate_dt);
  solver.step(scheme, time, dt, assemble);
  time += dt;
  ++step;
  if (output.due(step, time))
      output.write(step, time, solver.state());

limit_dt сокращает шаг до ближайшего срока среди всех зон с every_time.
Вызов due до запроса состояния позволяет получать один снимок с CPU или CUDA
только в моменты записи. Для периодической сетки передайте последним аргументом
конструктора std::vector<MeshIndex>(grid.node_dof, grid.node_dof + grid.original_node_count).
Значения из объединённых расчётных узлов попадут на соответствующие исходные
узлы. Полученный файл можно открыть в конвертере Tecplot вместе с исходной сеткой.

Проверки парсера, расписания и чтения сохранённых файлов входят в make
io-settings-test и io-settings-debug-test. Проект io_settings_tests с
WithCuda=true также проверяет запись снимка каждого доступного CUDA-устройства.

Консольный отчёт
----------------
Передайте объёмы тех же расчётных узлов и в том же порядке, что и в интеграторе.
При периодических связях используйте объединённые узлы и объёмы PeriodicDomain.
Вызовы в цикле расчёта. Номера шагов начинаются с 1.

  aero::FlowReport report(run.flowreport_every, run.gamma, dimension, grid.node_count, grid.volumes);
  // Для очередного шага с номером step
  report.capture(step, solver);
  solver.step(scheme, time, dt, assemble);
  time += dt;
  report.write(step, time, run.cfl, dt, solver);

Вызывайте write после успешного шага. При повторной попытке используйте тот же
номер и фактически принятый dt. Можно также передать в capture и write векторы
консервативных переменных в порядке [узел][компонента]. По умолчанию вывод
идёт в консоль. Последним аргументом write можно передать другой std::ostream.

Пример вывода в 2D

  Flow report    Step = 100    t = 0.875    CFL = 0.5    dt = 1.000000e-02

  Variable         Minimum        Maximum     Domain integral
  rho             1.000000       2.000000            1.750000
  ux             -1.000000       2.000000           -0.250000
  uy              0.000000       2.000000            1.500000
  p               1.000000       2.000000            1.750000
  E               4.500000      10.000000            8.625000

  Energy residual (volume-weighted RMS of dE/dt) = 1.802776e+00

Minimum и Maximum вычисляются по узлам. Domain integral равен Σ Vᵢ qᵢ.
Для скорости выводятся компоненты по размерности сетки. E означает плотность
полной энергии. Её временная невязка равна

  sqrt(Σ Vᵢ ((Eᵢⁿ − Eᵢⁿ⁻¹) / dt)² / Σ Vᵢ).

Например, на шаге 100 берутся энергии шагов 99 и 100. Для SSPRK3 это состояния
до первой и после третьей стадии. В сборке с OpenMP статистика вычисляется
параллельно на CPU. Для CUDA-интегратора два снимка поля передаются на CPU
только на отчётном шаге. Проверки запускаются через make io-flowreport-test
и make io-flowreport-cuda-test или проект io_flowreport_tests в Visual Studio.

LZMA доступна сетке, солверу и утилитам через общую статическую библиотеку.
Makefile: build/libaero_io.a, правила source/io/io.mk.
Visual Studio: проект msvs/aero_io.vcxproj в aero.sln.
Исходники LZMA SDK 24.09: third_party/lzma; установленный 7-Zip не требуется.
SDK компилируется как C с Z7_ST, обертка -- как C++11. CUDA не требуется.
Сжатие и файловый ввод-вывод выполняются на CPU; представление сетки для
CPU/CUDA не меняется. Для новых модулей подключать aero_io, не копировать SDK.

Сетка:
  mesh.write("grid.mesh", aero::MeshFormat::Lzma);
  aero::Mesh mesh = aero::Mesh::read("grid.mesh");

Mesh::read автоматически распознает Text, Binary и Lzma по сигнатуре.
Сжатый вариант содержит обычную бинарную сетку v2 без изменения топологии,
координат, имен границ или точности чисел. Старые Text/Binary остаются доступны.
По умолчанию запись остается Binary. Конвертер: --format lzma.
Это собственный блочный контейнер с LZMA1, а не файл .xz, .7z или .lzma-alone.

Формат контейнера AEROLZMA, версия 1:
  8 байт ASCII "AEROLZMA"
  uint32 версия = 1
  последовательность блоков:
    uint32 размер исходных данных (1..1048576)
    uint32 размер сжатых данных (1..1245184)
    uint32 CRC-32/ISO-HDLC исходных данных
    5 байт свойств LZMA1 (lc/lp/pb и размер словаря)
    сжатые данные LZMA1 с обязательным маркером конца
  uint32 ноль -- конец контейнера, после него данных быть не должно.
Все uint32 little-endian. CRC: отраженный полином 0xedb88320,
начальное значение и финальное XOR 0xffffffff.
Словарь не более 1048576 байт; каждый блок сжимается независимо.
Версия контейнера независима от версии вложенного формата сетки.

LzmaOutputBuffer пишет заголовок при создании, блоки по мере наполнения
буфера (1 МиБ) или flush(). Обязательно вызвать finish() перед закрытием
потока: он записывает оставшийся блок и терминатор. Деструктор не пишет.
LzmaInputBuffer создается после чтения сигнатуры и принимает ограничение
общего количества распакованных байт. Оба буфера не владеют исходным потоком;
его время жизни должно быть дольше времени жизни буфера.
Для передачи ошибок из streambuf включать exceptions(std::ios::badbit)
на оборачивающем std::istream/std::ostream. Чтение до EOF проверяет терминатор.
Низкоуровневый интерфейс бросает io::CompressionError; Mesh переводит его
в MeshError. Неуспешная запись может оставить частичный файл, как и Binary.

Проверяются размеры до выделения памяти, свойства LZMA, конец каждого блока,
точное потребление сжатых данных, CRC, отсутствие хвостовых данных.
MeshReadLimits применяются к распакованным массивам и именам, дополнительно
ограничивается длина распакованного бинарного потока (лимит + 88 байт заголовка).
Рабочая память кодека ограничена размером блока/словаря и не растет с файлом;
сама сетка и ее производные связи по-прежнему размещаются в памяти целиком.

Источники SDK и уведомление об авторстве: third_party/lzma/NOTICE.txt.
