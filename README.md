# Aero

Aero решает уравнения Эйлера на узлах одномерной, двумерной или трёхмерной сетки. В режиме `Equations = Euler` состояние узла хранится подряд в порядке плотность, компоненты импульса, полная энергия на единицу объёма. Для узла `i` первая компонента лежит по адресу `U + i * (dimension + 2)`.

## Турбулентность RANS, LES и DDES

В `main.txt` задайте `Turbulence = On`, `Equations = Euler` и молекулярную вязкость `normal` или `sutherland`. По умолчанию действует `Off`. Необязательный модуль находится в `source/turbulence` и использует вязкий оператор AES. При выключении модели файл её настроек не читается.

Для LES в turbulence.txt задайте `model = LES`, `les_eq = Sigma` и `subgridscale`. Поддерживаются `max`, `min`, `vol`, `Delta_omega`, `Delta_omega_tilde` и `sla`. Масштаб и градиент скорости вычисляются на исходных элементах AES. В узле усредняются кинематическая вязкость и кинематический VTM с весом, равным доле объёма элемента. Для SLA узловая вязкость умножается на квадрат F_KH от среднего VTM. Параметры `switch_on_vtm = off` или `F_KH_lim = 1` возвращают масштаб Δ̃ω. При нулевой завихренности направленные масштабы используют кубический корень из объёма. В неявной матрице ν_t фиксируется, в невязке пересчитывается по текущему полю. Группа вывода `turbulence` для LES содержит `nut`. [Модель Sigma](https://imag.umontpellier.fr/~yales2bio/PDF/Nicoud_2011.pdf), [формулы масштабов](https://pure.rug.nl/ws/portalfiles/portal/72010699/1.5012546_1_.pdf).

Для RANS в [turbulence.txt](templates/turbulence.txt) обязательны `model = RANS`, `rans_eq = SA` и `nut_nu_amb` — физическое отношение νt/ν∞. Параметр `pr_t` задаёт турбулентное число Прандтля, по умолчанию 0.9. Коэффициенты соответствуют стандартной положительной модели Спаларта — Аллмараса с ft2, без искусственного перехода. [Уравнение и константы модели](https://tmbwg.github.io/turbmodels/spalart.html).

Солвер задаёт начальную рабочую вязкость по набегающему потоку. На стенке с прилипанием (adiabatic_wall) он закрепляет ноль, на стенке со скольжением (novisc_wall) задаёт нулевой поток SA. На свободной границе входящий поток приносит заданное набегающее значение, выходящий уносит местное. Для переноса SA используется противопоточная аппроксимация первого порядка по потоку массы, для диффузии — геометрический оператор AES. У молекулярного и турбулентного тепловых потоков свои числа Прандтля. Для Эйлера и SSPRK3 обе вязкости пересчитываются на каждой стадии. BDF и steady проверяют неявное уравнение SA и газовый баланс на одном принятом состоянии. В пробах предиктора рабочая вязкость фиксируется до проверки связанного решения. Для записи рабочего поля укажите `nu_tilde` в `output.txt`, для физической кинематической вязкости — `nut`. Обе величины нормированы на U_ref·L_ref. Контрольная точка RANS хранит рабочую вязкость и её предыдущий слой при BDF2.

Для SA-DDES укажите в `turbulence.txt` параметры `model=DDES`, `rans_eq=SA`, `nut_nu_amb` и `subgridscale`. Все шесть масштабов и параметры SLA общие с LES Sigma. Коэффициент `c_des` по умолчанию равен 0.65. В переносе SA расстояние до стенки заменяется длиной DDES по Спаларту. Защита пристенного слоя зависит от суммы молекулярной и турбулентной вязкостей и от полной нормы градиента скорости. Для вывода и восстановления используются поля SA. [Формулы модели, уравнения (6)–(8)](https://www.cobaltcfd.com/pdfs/AIAA_2006_cylinder.pdf)

## Линеаризованные уравнения Эйлера

В `main.txt` выберите `Equations = Linear`. В [linear.txt](templates/linear.txt) задайте положительные фоновые плотность `rho0` и давление `p0`, а также компоненты фоновой скорости по размерности сетки. Для 1D нужна `ux0`, для 2D дополнительно `uy0`, для 3D ещё и `uz0`. Фон однороден в пространстве и постоянен во времени. Из `gamma` в `gas.txt` решатель вычисляет скорость звука `c0 = sqrt(gamma*p0/rho0)`.

В `init.txt`, на границе `free` и в выходных полях имена `rho, ux, uy, uz, p` означают **пульсации** плотности, скорости и давления. Например, `p = -10` задаёт отклонение давления на −10 Па от фона. При чтении составного консервативного поля солвер ожидает пульсации плотности, импульса и полной энергии на единицу объёма. В снимках и в таблице `E` означает пульсацию полной энергии на единицу объёма.

Режим свободной границы и шаг CFL определяются фоновой скоростью и `c0`. На неподвижной стенке фоновая скорость должна быть касательной. Пространственная матрица первого порядка для BDF1, BDF2 и steady постоянна. Решатель сохраняет её и обновляет вклад шага по времени в диагональ. Контрольная точка привязана к системе уравнений и фону.

Для разового изменения продольной фоновой скорости запустите расчёт такой командой.

```sh
aero main:Equations=Linear linear:ux0=-10
```

При отсутствии `Equations` используется `Euler`.

## Сравнение с точным решением

Параметр `exact_solution` в main.txt задаёт источник эталона. В режиме `formula` укажите в [exact.txt](templates/exact.txt) формулы для плотности, активных компонент скорости и давления. Для Linear задаются пульсации. В режиме `fields` укажите, например, `path = "../reference/final.fields"`. Снимок должен относиться к той же сетке. Он служит эталоном во все моменты вывода. Обычные узловые поля распознаются по именам, для других имён действуют привязки как в init.txt. Сохранённая энергия сравнивается напрямую, при её отсутствии энергия вычисляется из примитивных переменных. Нормы L₂ и L∞ выводятся в консоль и sol_error.txt в каталоге текущего запуска или продолжения. По умолчанию `exact_solution = off`. Прежнее значение `on` включает формулы.

Для каждой переменной с ошибкой в узле `e[i]` считаются `L_2 = sqrt(sum(V[i]*e[i]^2))` и `L_inf = max(abs(e[i]))`. В периодическом расчёте используется суммарный объём копий узла.

Формулы начального поля (`init.txt`) и точного решения (`exact.txt`) используют один язык. Координаты `x, y, z` задаются в единицах сетки. Для начального поля `t = 0`, для точного решения `t` равно времени отчёта. Доступны:

- Числа в десятичной и научной записи, константы `pi` и `e`, скобки, `+ - * / %`, степень `^` или `**`.
- Сравнения `< <= > >= == !=`, логика `! && ||` и `if(условие, да, нет)`. Условия вычисляют только необходимые ветви.
- `sin cos tan asin acos atan atan2 sinh cosh tanh` (углы в радианах).
- `exp expm1 log ln log2 log10 log1p sqrt cbrt pow abs hypot min max fmod floor ceil round erf erfc`. Функции `atan2(y,x)`, `hypot`, `pow`, `min`, `max`, `fmod` принимают два аргумента.

Например, `rho = 1 + 0.01*exp(-100*(x-0.3*t)^2)` задаёт движущийся профиль плотности.

## Как проследить один шаг

1. [Запуск](source/aero/main.cpp) читает [параметры расчёта](source/io/settings.cpp). После загрузки сетки [подготовка геометрии](source/aero/case_geometry.cpp) связывает имена участков с граничными условиями. [Начальное поле](source/initial/initial.cpp) вычисляется по формулам или читается из снимка.
2. [Медианные контрольные объёмы](source/cv/cv.cpp) дают объём каждого узла и вектор площади между концами каждого ребра. Внутренняя площадка ориентирована от `edge_begin` к `edge_end`. Внешняя площадка направлена из области.
3. [Сборка потока ребра](source/residual/residual_detail.h) начинается в `integrated_edge_flux`. По шаблону восстанавливаются левый и правый следы, ограничиваются плотность и давление, затем `solve_edge_flux` вызывает [Роу](source/eulersolver/roe.h) или [Русанова](source/eulersolver/lax_friedrichs.h). Площадь применяется один раз. Для внешней площадки состояние и поток определяют [граничные условия](source/bc/bc.h).
4. В невязку `R` первого узла внутренний поток входит со знаком плюс, второго — со знаком минус. Внешний поток относится к одному узлу. В [сборщике](source/residual/residual_detail.h) найдите `OrientedFace` и пройдите от списка площадок одного узла к сложению компонент. В [операторе подобласти](source/aero/partition_operator.cpp) видно, когда потоки передаются соседям.
5. По умолчанию (`cfl_method = height`) для каждого узла берётся наименьшая высота примыкающих ячеек. В невязком расчёте узловой шаг равен `CFL * h / (|u| + c)`. Вариант `cfl_method = spectral` использует прежнюю сумму по площадкам контрольного объёма. Глобальный шаг равен минимуму узловых. [Расчёт CFL](source/residual/flux_cfl.h) учитывает также вязкость и перенос SA. [choose_time_step](source/aero/time_loop.cpp) ограничивает шаг сроком вывода и конечным физическим временем.
6. [forward_euler_value](source/explicit/explicit_stage.h) обновляет одну компоненту по формуле `U − dt * R / V`. Для SSPRK3 [таблица стадий](source/explicit/ssprk3.cpp) задаёт время вычисления невязки и веса смешения. [Порядок стадий](source/explicit/stage_sequence.h) показывает, когда пересчитать потоки и передать обновлённые значения соседним процессам.
7. После принятия всего шага [цикл интегрирования](source/aero/time_loop.cpp) проверяет сроки отчёта, записи полей и контрольной точки. [Расписание зон](source/io/scheduled_output.cpp) определяет имена и наборы полей. [Восстановление](source/aero/recovery.cpp) проверяет хеш сетки и контрольные суммы перед продолжением расчёта.

### Пример для одного узла

Пусть у узла объём `V = 2`, плотность `ρ = 10` и шаг `dt = 0.1`. Через три площадки из контрольного объёма выходят потоки массы `+7`, `−5` и `+1`. Здесь положительное число означает выход, а площадь уже учтена. Сборщик складывает их и записывает `Rρ = 3` в компоненту плотности. На общем ребре тот же поток входит в соседний узел с противоположным знаком.

| Стадия | Откуда берём состояние | Плотность после стадии |
|---|---|---|
| Эйлер или первая стадия SSPRK3 | Из начала шага | `Y1 = 10 − 0.1 × 3 / 2 = 9.85` |
| Вторая стадия SSPRK3 | Шаг Эйлера из `Y1`, затем смешение с началом шага | `Y2 = 3/4 × 10 + 1/4 × (9.85 − 0.15) = 9.925` |
| Третья стадия SSPRK3 | Шаг Эйлера из `Y2`, затем смешение с началом шага | `U_next = 1/3 × 10 + 2/3 × (9.925 − 0.15) = 9.85` |

В примере сумма потоков постоянна для простоты счёта. В солвере перед второй стадией невязка собирается из `Y1`, перед третьей — из `Y2`. Для импульса и энергии интегратор применяет тот же расчёт к соответствующей компоненте невязки.

### Что означает номер узла в MPI

В исходном файле сетки узел имеет глобальный номер. В архиве разделов пара «лист, смещение» указывает, где лежит его запись. После чтения раздела узел получает локальный номер, по которому можно обратиться к координатам и соседям. Если узел лежит на периодическом шве, несколько геометрических узлов используют одно состояние. Для вычисления потока нужен индекс именно этого состояния. [Чтение раздела](source/mesh/partition.cpp), [склейка шва](source/aero/mpi_periodic.cpp), [индексы состояний для реконструкции](source/aero/mpi_stencil.cpp).

## Сборка Kokkos для NVIDIA в один EXE

На Windows откройте терминал MSYS2 MinGW64. Для сборки нужны GCC, CMake, Python, Clang с поддержкой CUDA, компоновщик LLD, CUDA Toolkit 12 и инструменты C++ Visual Studio x64. Команда использует локальную копию Kokkos 3.2.01 и стандарт C++11.

В Windows обычный `make` собирает `bin/aero.exe` в Release с Kokkos CUDA, MPI и статической линковкой. Make использует Clang и LLD из PATH, если они установлены. При необходимости он распаковывает комплект из `third_party/mingw-llvm` в `tools/mingw-llvm`. После удаления `build` комплект остаётся на месте, а Kokkos собирается заново из архива в `third_party`.

```sh
make -j"$(nproc)"
```

Для сборки солвера только под CPU используйте `make aero KOKKOS_BACKEND=cpu`. В Linux по умолчанию выбирается CPU. Сборка с `KOKKOS_BACKEND=cuda` поддерживает CPU и GPU NVIDIA. Для AMD в Linux выполните `make -j aero BUILD_TYPE=Release KOKKOS_BACKEND=hip HIP_ARCH=gfx90a`. Параметр `HIP_ARCH` задаёт цель компилятора hipcc (gfx900, gfx906, gfx908, gfx90a или gfx942). При нестандартной установке ROCm укажите `HIPCC=/путь/к/hipcc ROCM_PATH=/путь/к/rocm`. Исполняемый файл HIP также может работать на CPU.

Для переносимой постановки задайте `backend=gpu` в `main.txt` и `devices=0` в `gpu.txt`. Тип GPU определяется сборкой, номер устройства выбирается при запуске. Для явного выбора HIP поддерживается `backend=hip` с тем же файлом `gpu.txt`. Существующие постановки с `backend=cuda` читают список карт из `cuda.txt`.

В Ubuntu проверьте `command -v nvcc` и `nvcc --version`, затем запустите `make -j"$(nproc)" aero BUILD_TYPE=Release KOKKOS_BACKEND=cuda`. Make определяет каталог CUDA Toolkit по выбранному `nvcc` и передаёт его CMake при настройке Kokkos. Для пакетной установки с `/usr/bin/nvcc` корнем обычно служит `/usr`. При нескольких версиях Toolkit можно добавить к команде `CUDA_HOME=/путь/к/toolkit` или `CUDAToolkit_ROOT=/путь/к/toolkit`. Строка `GPU` в начале сборки показывает фактический выбор.

В неявном газовом решателе `make aero` по умолчанию использует `MIXED_LINEAR=1`. В этом режиме внедиагональные блоки якобиана хранятся в `float`. Диагональные блоки, LU-разложение, векторы BiCGSTAB, суммы при умножении на матрицу и нормы вычисляются в `double`. Критерий остановки проверяет фактическую невязку записанной матрицы. Параметр `compact_jacobian` в `implicit.txt` независимо задаёт набор связей между узлами.

Для полностью двойной точности линейного решателя соберите `make aero MIXED_LINEAR=0`. Режим отображается в строке `Linear solve` при сборке. На явное интегрирование этот флаг не влияет.

В начале сборки Make печатает выбранный исполнитель Kokkos, настройки MPI, OpenMP, CGNS и статической линковки, затем фактические флаги компилятора и компоновщика. Дальше каждая строка показывает действие и файл, например `Compiling    source/aero/solver.cpp`. Чтобы увидеть также полные команды, добавьте `V=1` к обычному вызову Make. Предупреждения и ошибки видны в обоих режимах.

Для переноса расчёта достаточно файла `bin/aero.exe`. Код Kokkos, среда выполнения CUDA и OpenMP включены в EXE. На машине для расчёта нужен драйвер NVIDIA. В `main.txt` параметр `backend = cuda` выбирает GPU, а `backend = cpu` запускает тот же файл на процессоре. Если Clang установлен отдельно, его путь для сборки задаёт `KOKKOS_GPU_CXX`.

Один и тот же EXE запускается напрямую и через `mpiexec`. Сборка по умолчанию включает MPI. На Windows нужен установленный MS-MPI, на Linux — компилятор MPI и его среда выполнения.

`aero --help` выводит краткую справку. Пустой запуск или пропущенный аргумент также выводит справку и возвращает код ошибки. Для обычного расчёта в текущем каталоге со значениями из файлов запустите `aero --input=. --output=.`.

Из каталога постановки можно запустить `aero main:cfl=0.4 gas.txt:gamma=1.4 main:upw_coeff=0.8`. Значения действуют на один запуск. Поддерживаются параметры main.txt, gas.txt, cuda.txt, scheme.txt, implicit.txt, cfl.txt, linear.txt и turbulence.txt (при сборке с модулем), расширение можно опустить. При повторе ключа действует последнее значение. Без параметров каталогов ввод и вывод находятся в текущей папке.

Для неявного расчёта задайте в main.txt `time_scheme = BDF1` или `BDF2` и скопируйте [implicit.txt](templates/implicit.txt) в каталог постановки. BDF2 начинает с одного шага неявного Эйлера, затем учитывает длины двух соседних шагов. Контрольная точка BDF2 сохраняет предыдущий слой и длину принятого шага. При запуске из старой контрольной точки BDF2 снова начинает с одного шага BDF1.

Для выхода на стационар задайте в main.txt `time_scheme = steady`. Решатель делает псевдошаги неявного Эйлера с заданным CFL. В конце каждого шага он вычисляет `M = max |Rᵢₖ|/Vᵢ` по всем узлам, компонентам и процессам MPI. В implicit.txt выберите `steady_criterion = relative` для остановки при `M/M₀ <= steady_tol` или `absolute` для остановки при `M <= steady_tol`. При продолжении из recovery решатель использует норму M₀ самого первого слоя расчёта. Для старого формата он восстанавливает её по сохранённому начальному полю. Равновесное начальное поле принимается сразу. При достижении `steady_max_steps` с начала расчёта решатель записывает последние поля и сообщает о недостижении допуска. В режиме steady время в файлах означает псевдовремя.

Чтобы использовать локальный псевдошаг, задайте в implicit.txt `local_time_step = on` (по умолчанию `off`). Каждый собственный узел использует свой шаг CFL для газа и SA. Параметр `local_time_step_max_ratio` ограничивает шаг сверху произведением коэффициента на минимум всей сетки. По умолчанию ограничение выключено (`off`). Значение 1 даёт общий минимальный шаг. Для `t_fo`, вывода по времени и recovery отсчитывается сумма принятых минимальных шагов. Если расписание укорачивает шаг, все узловые шаги уменьшаются в одинаковой пропорции. В отчёте выводятся диапазон шагов и среднеквадратичное изменение энергии за итерацию. В режиме `local_time_step = auto` каждый узел адаптирует шаг по изменениям плотности, давления, скорости и рабочей вязкости SA. После адаптации на каждом шаге применяется тот же предел относительно текущего минимума по всей сетке. Верхний предел узлового шага пересчитывается на каждом принятом слое по текущему CFL. Метод `height` использует высоту ячеек, `spectral` — скорости распространения на площадках контрольного объёма. Оба учитывают вязкость и перенос SA. После несходимости BiCGSTAB солвер повторяет попытку с половиной фактического шага. После перезапуска auto заново строит начальное распределение по текущему полю. Для сравнения скорости установления используйте время работы до одинаковой пространственной невязки.

Для `local_time_step_residual_limit = on` и `stencil` владелец узла раз в 32 принятых шага сравнивает модули невязок газа и SA с их собственными средними. Рост учитывается при одновременном превышении 1% максимума по сетке и 105% среднего. В `stencil` достаточно роста хотя бы в одном узле действующего шаблона реконструкции. Для SA учитывается направление конвективного потока. При росте предел снижается до 75% предыдущего узлового шага с поправкой на изменение CFL и с нижней границей по прежнему минимуму. При отсутствии роста допустимая доля CFL увеличивается в 1,25 раза до единицы.

В `implicit.txt` параметры `local_time_step_density_change`, `local_time_step_pressure_change` и `local_time_step_velocity_change` по умолчанию равны 0.01, а `local_time_step_sa_change` — 0.05. Для каждого узла auto сравнивает нормированные изменения с этими целями и выбирает наибольшее отношение. `local_time_step_min_factor` и `local_time_step_max_factor` ограничивают множитель адаптации снизу и сверху. По умолчанию границы равны 0.5 и 1.25.

Чтобы управлять диапазоном узловых шагов по сходимости и затратам на СЛАУ, задайте в `implicit.txt` параметры `local_time_step = auto` и `local_time_step_residual_limit = work`. Для этой оценки используются общая норма невязки и число итераций BiCGSTAB. Режим `stencil` сочетает такую же оценку с местной проверкой роста невязки по шаблону.

В режиме `local_time_step_residual_limit = cfl` солвер вычисляет и адаптирует узловые шаги при CFL=1, применяет предел `work` и заданные ограничения отношения шагов, включая соседние узлы. Затем каждый шаг умножается на текущий CFL. При пределе 1 и CFL=100 все узлы получают один шаг, равный 100 минимальным базовым шагам. В отчёте указаны фактически принятые шаги.

В режимах `work`, `cfl` и `stencil` первые 32 принятых шага каждой реконструкции используют общий минимум. Затем солвер пересматривает верхнюю границу отношения `dt_max/dt_min` после каждого блока из 32 шагов. Он сравнивает геометрические средние нормы пространственной невязки в двух половинах блока. При снижении нормы диапазон расширяется с учётом числа итераций BiCGSTAB по всем поправкам Ньютона и отношения начальной нормы этой реконструкции к текущей. Если норма остаётся постоянной или растёт, новым пределом становится квадратный корень из предыдущего. При переходе с первого порядка отсчёт начинается с поля перед первым шагом новой схемы.

Recovery сохраняет исходную норму выбранной реконструкции, текущий предел, наблюдения внутри незавершённого блока и затраты на предыдущий блок. Если старый recovery содержит только исходную норму, она используется для нового блока с начальным пределом 1. Ручной `local_time_step_max_ratio` может дополнительно уменьшить предел. Команда изменения этого коэффициента сохраняет наблюдения. Строка `LTS step ratio limit` показывает предел на принятом шаге.

Для наблюдения задайте в `local_time_step_probe_node` глобальный номер узла. Отчёт покажет его фактический шаг, невязки газа и SA и разрешённую долю шага CFL. Если отчёт совпал с проверкой, выводится номер узла шаблона, вызвавшего ограничение. Подробности приведены в [implicit.txt](templates/implicit.txt).

Параметр `local_time_step_neighbor_ratio` в implicit.txt ограничивает отношение шагов на каждом ребре в режимах `on` и `auto`. Например, при значении 2 соседние узлы могут различаться по шагу не более чем вдвое. После применения общего предела решатель уменьшает большие шаги до выполнения условия на всех рёбрах, в том числе между процессами MPI. В строке `LTS edge ratio` отчёта видны максимальные отношения до и после этого ограничения. По умолчанию параметр равен `off`.

В implicit.txt параметр `simplified_newton = on` включает упрощённый метод Ньютона для BDF1, BDF2 и steady. Матрица первой поправки и предобусловливатель используются до конца шага. После каждой поправки пересчитываются потоки и проверяется полная нелинейная невязка. При явном `off` матрица нелинейной задачи обновляется на каждой поправке. По умолчанию режим задаёт `jacobian_update_every`. При явном `on` нулевой интервал действует как 1. Без переключателя параметр `jacobian_update_every` задаёт частоту обновления пространственных производных. При 0 они обновляются на каждой поправке Ньютона, при 1 — на первой поправке каждого шага, при N — с интервалом N принятых шагов. Если шаг уже решил предиктор, собирать матрицу на этом шаге не требуется. При новом шаге вклад BDF в диагональ и его разложение обновляются перед первым линейным решением. Для начального приближения решатель пробует итерации Пикара с временной диагональю и проверяет каждую по полной невязке. При слабом уменьшении невязки вязкий предиктор дополнительно пробует часть поправки, выбранную по отношению норм. Каждую пробу решатель проверяет по полной невязке BDF. При неудаче он восстанавливает последнее принятое приближение и переходит к Ньютону.

В BDF1, BDF2 и steady предиктор включён при любом `newton_max_iter`, в том числе при 1. При `newton_without_predictor = on` Ньютон начинает с принятого газового поля. По умолчанию переключатель равен `off`.

Для общего шага газа в BDF1, BDF2 и steady параметр `predictor_history_order = 1…6` разрешает начальное приближение по предыдущим принятым слоям. По умолчанию он равен 0. На пробе решатель проверяет полное уравнение BDF с тем же `newton_tol`. В steady RANS с SA и `local_time_step = auto` отдельный предиктор использует пространственные балансы газа и узловые псевдошаги. Решатель проверяет газ и SA на одном поле, при необходимости собирает якобиан и выполняет поправку Ньютона. [Описание неявного шага](source/implicit/README.md)

Ньютон решает полный баланс на новом слое с потоком и реконструкцией из main.txt. В implicit.txt параметр `jacobian_flux` выбирает LF или Roe для матрицы поправки первого порядка. При `simplified_jacobian = on` фиксируется скорость диссипации LF или матрица диссипации Роу. Значение `off` включает полную производную этого потока. Диагональные блоки пространственной части определяются из баланса потоков. При запуске через MPI каждый процесс хранит строки своих узлов, а производные на общем ребре вычисляет один владелец.

BiCGSTAB принимает `preconditioner = BJ` или `CSGS`. CSGS использует раскраску сеточного графа на GPU и последовательный обход внутри подобластей на CPU. Между прямым и обратным проходами ранги обмениваются значениями на стыках. На GPU каждому процессу назначается карта. В отчётный шаг report показывает достигнутую относительную невязку Ньютона. [Алгоритм Магомедова и Горобца](https://cs.msu.ru/sites/cmc/files/docs/gorobec.pdf)

Для MP5 или MPWENO5 задайте `reconstruction = mp5` или `reconstruction = MPWENO5` в main.txt. В необязательном scheme.txt параметр `mp6_hybrid` задаёт вес ограниченной центральной поправки на полном шаблоне (0…1, по умолчанию 0). У MPWENO5 параметр `mpweno_ad_corr = on` включает антидиссипативную поправку к нелинейным весам, `off` выключает её. По умолчанию поправка включена. Пример запуска: `aero main:reconstruction=MPWENO5 scheme:mp6_hybrid=1 scheme:mpweno_ad_corr=on`.

При включённом гибриде MP6 обе акустические характеристики и энтропийная характеристика используют общий вес, а каждая поперечная — свой. В режиме `flux` солвер сначала восстанавливает значения слева и справа от грани по координатным осям. Затем он вычисляет поправку MP6. Для массы, нормального импульса и энергии (или их потоков) действует общий вес, для касательных составляющих импульса — местное ограничение. При стремлении `mp6_hybrid` к нулю поправка исчезает.

`upw_coeff` в main.txt масштабирует диссипативную часть потоков LF и Roe от 0 (центральный поток) до 1 (полная диссипация по умолчанию). Для CFL используется полная оценка скорости волн.

В EBR3 и EBR5 тот же параметр управляет реконструкцией на ребре. До ограничения солвер сохраняет среднее двух следов EBR и умножает их разность на `upw_coeff`. При 0 обе стороны получают общий центральный след, при 1 сохраняется чистая EBR. В режиме `flux` солвер смешивает таким способом и состояния, и физические потоки. На рёбрах с принудительными узловыми следами действует только множитель диссипации LF/Roe.


## Как проверить изменение

`make -j32 test` собирает и запускает модульные проверки. Для сборки и проверки MPI укажите `WITH_MPI=1`. Число после `-j` задаёт число одновременно выполняемых заданий сборки. Число вычислительных потоков задают `omp_threads` в постановке или `OMP_NUM_THREADS`.

Решение Visual Studio [aero.sln](msvs/aero.sln) собирает проекты тем же GNU Make. По умолчанию все проекты используют CUDA, OpenMP и MPI со статической линковкой CUDA Runtime. Для CPU передайте MSBuild параметр `/p:KokkosBackend=cpu`. Если MSYS2 установлен вне C:\msys64, задайте его корневой каталог в переменной среды MSYS2_ROOT.

`make -j32 programs` собирает программы. После этого `python qa/run.py --case sod_1d` сравнивает расчёт с точным решением задачи Сода. Команда `python qa/run.py` проходит всю матрицу. Варианты CUDA и MPI, расположение результатов и допуски описаны в [руководстве по QA](qa/README.md).

## Начальный расчёт с первым порядком

Параметр `t_fo` в `main.txt` задаёт время перехода от первого порядка по пространству во всех узлах к схеме `reconstruction`. Например, при `t_fo = 1` шаг, заканчивающийся в момент 1, выполняется с первым порядком на всех стадиях. Следующий шаг использует заданную реконструкцию и действующие локальные метки `low` или `on`. При `t_fo = 0` (по умолчанию) выбранная схема работает с начала расчёта. При продолжении из контрольной точки используется восстановленное время.

Для `steady` граница задаётся по псевдовремени. При завершении `t_fo` или `steps_fo` пространственная невязка принятого поля сразу пересчитывается по схеме `reconstruction`, до проверки сходимости и отчёта. Это действует и при остановке точно на границе стартового участка. Последний шаг первого порядка не включается в статистику работы локальных шагов новой схемы. Лимит числа псевдошагов относится ко всему расчёту.

## Стабилизация шага Эйлера

Параметр `stabilization` в `main.txt` применяется к уравнениям Euler с явным или неявным интегратором. По умолчанию задано `off`: используется обычный `cfl` из `main.txt`, недопустимое состояние останавливает расчёт. Для Linear используется `off`.

В режимах `cfl`, `low` и `on` начальное число Куранта задаёт `cfl_init` в `cfl.txt`. При неположительной плотности или давлении солвер восстанавливает принятый слой, делит CFL на `cfl_coeff` и повторяет тот же шаг. Значение ниже `cfl_min` завершает расчёт с ошибкой. После каждых `cfl_num_steps` последовательных успешных шагов CFL умножается на `cfl_coeff` до `cfl_max`. Требуются `0 < cfl_min <= cfl_init <= cfl_max`, `cfl_coeff > 1` и целое `cfl_num_steps >= 1`.

В режиме `low` или `on` со стороны отказавшего узлового контрольного объёма берётся значение первого порядка. Соседняя сторона ребра сохраняет свою реконструкцию. В режиме `low` все метки сбрасываются при подъёме CFL до 99 % максимума, в режиме `on` метки сохраняются и при продолжении из контрольной точки. В режиме `cfl` меняется только число Куранта и зависящий от него коэффициент MP.

В Report процесс 0 выводит `failed since last report` (различные отказавшие узлы с предыдущего отчёта) и `first-order now` (число узлов с принудительным первым порядком на отчётном шаге, либо все узлы для схемы `first_order`). При откате строка RETRY сразу показывает номер шага, прежний и новый CFL и число отказавших узлов этой попытки. Копии узлов в соседних MPI-процессах не увеличивают счётчики.

При запуске на GPU резервная копия для отката остаётся в памяти карты. На явной стадии Kokkos проверяет собственные узлы при их обновлении, на итерации Ньютона — после обмена полями с соседями. Процессор получает число отказов и локальные номера отказавших узлов, которые переводит в глобальную нумерацию для отчёта MPI.

Строка `Placing ... arrays on GPU` показывает только постоянные массивы подобласти. Полный план выводится отдельно в `GPU memory plan`: массивы реконструкции и кэши, дополнительная память неявного решателя, multigrid, их сумма и доступный бюджет. Все размеры в этой строке указаны в десятичных GB (1 GB = 10⁹ байт), с шестью знаками после запятой. Это расчёт размера буферов, а не показание занятой видеопамяти: контекст CUDA и рабочие данные драйвера также занимают место. Для диагностики каждого выделения можно задать переменную среды `AERO_GPU_MEMORY_TRACE=1`.

Общие наклоны WENO/MP и центральные разности используют одну геометрическую запись, если номера узлов и коэффициенты совпадают точно. WENO3 не хранит пустые позиции дальних наклонов. Индексы CSR для EBR и длинных строк WENO занимают 32 бита, если размер сетки и таблицы это допускает; иначе сохраняются 64 бита. На время поиска грубой поправки multigrid использует свободные векторы BiCGSTAB; перед вычислением пробных потоков эти направления больше не нужны. Коэффициенты схем и порядок суммирования при этом сохраняются.

Геометрия площадок и вязких элементов, связность и срезы градиентов также упаковывают целые номера. Формат выбирается по значениям всей таблицы, включая смещения и бит ориентации грани, и не зависит от модели GPU. При превышении `UINT32_MAX` сохраняется исходная 64-битная таблица. Координаты, площади и коэффициенты остаются `double`; адресная арифметика выполняется с широкими индексами. Это применяется ко всем схемам и типам сеток, в том числе смешанным и периодическим.

На одной карте резервная копия для отката может одновременно хранить начало шага SSPRK или BDF1. При MPI, где отличаются полная и собственная нумерации, используются отдельные поля. BDF2 сохраняет собственную историю; переход с BDF1 на BDF2 отсоединяет заимствованный буфер до записи нового шага.

Multigrid хранит две массы на агрегат: для плотности/энергии и для импульса с учётом прилипания. Его связность использует тот же выбор 32/64 бит. Если после направлений поиска в Krylov остаётся целый вектор, туда помещается временное произведение матрицы на вектор, а поле коррекции Ньютона сохраняет сглаживатель. Это включается только при гарантии, что проверка пробной невязки не перезапишет коррекцию; иначе сохраняется отдельный буфер.

При `jacobian_update_every=1` готовая матрица используется только внутри одного шага Ньютона, поэтому отдельная копия её пространственной диагонали не выделяется. Для переноса матрицы между шагами и для линейных уравнений копия сохраняется.

## Управление запущенным расчётом

Солвер создаёт **`control.txt`** в корне каталога `--output`. Введите команды и сохраните файл. Как только солвер прочитает содержимое, он очистит файл на месте, даже если в командах есть ошибка. Результат обработки попадёт в консоль и в `aero.log`. После сообщения можно сохранить следующий набор команд, в том числе повторить предыдущий.

Солвер проверяет команды после первого принятого шага запуска и далее на шагах, кратных `control_every` из `main.txt`. По умолчанию интервал равен 16 шагам, значение 1 включает проверку на каждом шаге, 0 отключает её. В MPI файл читает процесс 0. Подтверждение `Control accepted` содержит имя команды и принятое значение. Неизвестный ключ вызывает предупреждение, остальные команды применяются. При ошибке в значении известной команды солвер сообщает `Control rejected` и продолжает с прежними параметрами.

Консольный вывод солвера, включая отчёты, предупреждения и ошибки, сохраняется в **`aero.log`** в корне `--output`. При повторном запуске новые сообщения дописываются в конец того же журнала.

Каждая строка задаёт одно действие. Включайте только нужные строки.

```text
upw_coeff = 0.85
mp6_hybrid = 0.4
cfl = 0.5
cfl_min = 0.01
cfl_max = 1
cfl_num_steps = 20
cfl_coeff = 1.5
# Только при time_scheme = steady
local_time_step = on
local_time_step_max_ratio = 4
reset_fail
```

Оба веса принимают значения от 0 до 1. Команда `cfl` задаёт число Куранта следующего шага. В режиме `steady` команда `local_time_step = off` возвращает общий шаг, `on` включает локальный шаг CFL, `auto` включает автоматический выбор по изменению полей со следующего шага. Ограничение `local_time_step_max_ratio` можно задавать отдельно, в том числе заранее при общем шаге. Значение `off` снимает ограничение. Обе настройки, изменённые через `control.txt`, сохраняются в recovery. При активной стабилизации изменение настроек CFL начинает отсчёт успешных шагов заново. Если меняются только границы, солвер приводит текущий CFL к новому диапазону. Явно заданный CFL должен в него попадать. Границы, множитель и интервал применяются в режимах `cfl`, `low` и `on`. Имена `cfl_num_steps` и `cfl_coeff` одинаковы в обоих файлах. Из командной строки их можно задать как `aero cfl:cfl_num_steps=20 cfl:cfl_coeff=1.5`.

Команда `reset_fail` снимает со всех узлов метки пониженного порядка, включая постоянные метки режима `on`. История отказов для очередного отчёта сохраняется. Условие `t_fo` продолжает действовать.

При обычном завершении и по команде `STOP` солвер запишет все зоны из `output.txt` и контрольную точку на принятом шаге, в том числе при `recovery_every_steps = 0`. Продолжить можно с `--recover`. Контрольная точка сохраняет введённые во время расчёта настройки, метки и предыдущий слой BDF2.
