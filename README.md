# Aero

Aero решает уравнения Эйлера на узлах одномерной, двумерной или трёхмерной сетки. В режиме `Equations = Euler` состояние узла хранится подряд в порядке плотность, компоненты импульса, полная энергия на единицу объёма. Для узла `i` первая компонента лежит по адресу `U + i * (dimension + 2)`.

## Линеаризованные уравнения Эйлера

В `main.txt` выберите `Equations = Linear`. В [linear.txt](templates/linear.txt) задайте положительные фоновые плотность `rho0` и давление `p0`, а также компоненты фоновой скорости по размерности сетки. Для 1D нужна `ux0`, для 2D дополнительно `uy0`, для 3D ещё и `uz0`. Фон однороден в пространстве и постоянен во времени. Из `gamma` в `gas.txt` решатель вычисляет скорость звука `c0 = sqrt(gamma*p0/rho0)`.

В `init.txt`, на границе `free` и в выходных полях имена `rho, ux, uy, uz, p` означают **пульсации** плотности, скорости и давления. Например, `p = -10` задаёт отклонение давления на −10 Па от фона. При чтении составного консервативного поля солвер ожидает пульсации плотности, импульса и полной энергии на единицу объёма. В снимках и в таблице `E` означает пульсацию полной энергии на единицу объёма.

Режим свободной границы и шаг CFL определяются фоновой скоростью и `c0`. На неподвижной стенке фоновая скорость должна быть касательной. Пространственная матрица первого порядка для BDF1, BDF2 и steady постоянна. Решатель сохраняет её и обновляет вклад шага по времени в диагональ. Контрольная точка привязана к системе уравнений и фону.

Для разового изменения продольной фоновой скорости запустите расчёт такой командой.

```sh
aero main:Equations=Linear linear:ux0=-10
```

При отсутствии `Equations` используется `Euler`.

## Сравнение с точным решением

Параметр `exact_solution` в main.txt задаёт источник эталона. В режиме `formula` укажите в [exact.txt](templates/exact.txt) формулы для плотности, активных компонент скорости и давления. Для Linear задаются пульсации. В режиме `fields` укажите, например, `path = "../reference/final.fields"`. Снимок должен относиться к той же сетке. Он служит эталоном во все моменты вывода. Обычные узловые поля распознаются по именам, для других имён действуют привязки как в init.txt. Сохранённая энергия сравнивается напрямую, при её отсутствии энергия вычисляется из примитивных переменных. Нормы L₂ и L∞ выводятся в консоль и sol_error.txt в каталоге текущего запуска или продолжения. По умолчанию `exact_solution = off`. Прежнее значение `on` включает формулы.

Для каждой переменной с ошибкой в узле `e[i]` считаются `L_2 = sqrt(sum(V[i]*e[i]^2))` и `L_inf = max(abs(e[i]))`. В периодическом расчёте используется суммарный объём копий узла.

Формулы начального поля (`init.txt`) и точного решения (`exact.txt`) используют один язык. Координаты `x, y, z` задаются в единицах сетки. Для начального поля `t = 0`, для точного решения `t` равно времени отчёта. Доступны:

- Числа в десятичной и научной записи, константы `pi` и `e`, скобки, `+ - * / %`, степень `^` или `**`.
- Сравнения `< <= > >= == !=`, логика `! && ||` и `if(условие, да, нет)`. Условия вычисляют только необходимые ветви.
- `sin cos tan asin acos atan atan2 sinh cosh tanh` (углы в радианах).
- `exp expm1 log ln log2 log10 log1p sqrt cbrt pow abs hypot min max fmod floor ceil round erf erfc`. Функции `atan2(y,x)`, `hypot`, `pow`, `min`, `max`, `fmod` принимают два аргумента.

Например, `rho = 1 + 0.01*exp(-100*(x-0.3*t)^2)` задаёт движущийся профиль плотности.

## Как проследить один шаг

1. [Запуск](source/aero/main.cpp) читает [параметры расчёта](source/io/settings.cpp). После загрузки сетки [подготовка геометрии](source/aero/case_geometry.cpp) связывает имена участков с граничными условиями. [Начальное поле](source/initial/initial.cpp) вычисляется по формулам или читается из снимка.
2. [Медианные контрольные объёмы](source/cv/cv.cpp) дают объём каждого узла и вектор площади между концами каждого ребра. Внутренняя площадка ориентирована от `edge_begin` к `edge_end`. Внешняя площадка направлена из области.
3. [Сборка потока ребра](source/residual/residual_detail.h) начинается в `integrated_edge_flux`. По шаблону восстанавливаются левый и правый следы, ограничиваются плотность и давление, затем `solve_edge_flux` вызывает [Роу](source/eulersolver/roe.h) или [Русанова](source/eulersolver/lax_friedrichs.h). Площадь применяется один раз. Для внешней площадки состояние и поток определяют [граничные условия](source/bc/bc.h).
4. В невязку `R` первого узла внутренний поток входит со знаком плюс, второго — со знаком минус. Внешний поток относится к одному узлу. В [сборщике](source/residual/residual_detail.h) найдите `OrientedFace` и пройдите от списка площадок одного узла к сложению компонент. В [операторе подобласти](source/aero/partition_operator.cpp) видно, когда потоки передаются соседям.
5. Для CFL важны модуль площади и скорость волн каждой площадки. [Расчёт для узла](source/timestep/cfl_detail.h) даёт `2 * CFL * V / sum(speed * area)`. Глобальный минимум ограничивает шаг всей области. [choose_time_step](source/aero/time_loop.cpp) учитывает также срок вывода и конечное физическое время.
6. [forward_euler_value](source/explicit/explicit_stage.h) обновляет одну компоненту по формуле `U − dt * R / V`. Для SSPRK3 [таблица стадий](source/explicit/ssprk3.cpp) задаёт время вычисления невязки и веса смешения. [Порядок стадий](source/explicit/stage_sequence.h) показывает, когда пересчитать потоки и передать обновлённые значения соседним процессам.
7. После принятия всего шага [цикл интегрирования](source/aero/time_loop.cpp) проверяет сроки отчёта, записи полей и контрольной точки. [Расписание зон](source/io/scheduled_output.cpp) определяет имена и наборы полей. [Восстановление](source/aero/recovery.cpp) проверяет хеш сетки и контрольные суммы перед продолжением расчёта.

### Пример для одного узла

Пусть у узла объём `V = 2`, плотность `ρ = 10` и шаг `dt = 0.1`. Через три площадки из контрольного объёма выходят потоки массы `+7`, `−5` и `+1`. Здесь положительное число означает выход, а площадь уже учтена. Сборщик складывает их и записывает `Rρ = 3` в компоненту плотности. На общем ребре тот же поток входит в соседний узел с противоположным знаком.

| Стадия | Откуда берём состояние | Плотность после стадии |
|---|---|---|
| Эйлер или первая стадия SSPRK3 | Из начала шага | `Y1 = 10 − 0.1 × 3 / 2 = 9.85` |
| Вторая стадия SSPRK3 | Шаг Эйлера из `Y1`, затем смешение с началом шага | `Y2 = 3/4 × 10 + 1/4 × (9.85 − 0.15) = 9.925` |
| Третья стадия SSPRK3 | Шаг Эйлера из `Y2`, затем смешение с началом шага | `U_next = 1/3 × 10 + 2/3 × (9.925 − 0.15) = 9.85` |

В примере сумма потоков постоянна для простоты счёта. В солвере перед второй стадией невязка собирается из `Y1`, перед третьей — из `Y2`. Для импульса и энергии интегратор применяет тот же расчёт к соответствующей компоненте невязки.

### Что означает номер узла в MPI

В исходном файле сетки узел имеет глобальный номер. В архиве разделов пара «лист, смещение» указывает, где лежит его запись. После чтения раздела узел получает локальный номер, по которому можно обратиться к координатам и соседям. Если узел лежит на периодическом шве, несколько геометрических узлов используют одно состояние. Для вычисления потока нужен индекс именно этого состояния. [Чтение раздела](source/mesh/partition.cpp), [склейка шва](source/aero/mpi_periodic.cpp), [индексы состояний для реконструкции](source/aero/mpi_stencil.cpp).

## Сборка Kokkos для NVIDIA в один EXE

На Windows откройте терминал MSYS2 MinGW64. Для сборки нужны GCC, CMake, Python, Clang с поддержкой CUDA, компоновщик LLD, CUDA Toolkit 12 и инструменты C++ Visual Studio x64. Команда использует локальную копию Kokkos 3.2.01 и стандарт C++11.

```sh
make -j"$(nproc)" programs KOKKOS_BACKEND=cuda STATIC_LINK=1 CUDA_ARCH=86
```

По умолчанию Make собирает Kokkos для CPU. Явно задать эту конфигурацию можно через `KOKKOS_BACKEND=cpu`. Сборка с `KOKKOS_BACKEND=cuda` поддерживает CPU и GPU NVIDIA.

В начале сборки Make печатает выбранный исполнитель Kokkos, настройки MPI, OpenMP, CGNS и статической линковки, затем фактические флаги компилятора и компоновщика. Дальше каждая строка показывает действие и файл, например `Compiling    source/aero/solver.cpp`. Чтобы увидеть также полные команды, добавьте `V=1` к обычному вызову Make. Предупреждения и ошибки видны в обоих режимах.

Для переноса расчёта достаточно файла `bin/aero.exe`. Код Kokkos, среда выполнения CUDA и OpenMP включены в EXE. На машине для расчёта нужен драйвер NVIDIA. В `main.txt` параметр `backend = cuda` выбирает GPU, а `backend = cpu` запускает тот же файл на процессоре. Если Clang установлен отдельно, его путь для сборки задаёт `KOKKOS_GPU_CXX`.

Один и тот же EXE запускается напрямую и через `mpiexec`. Сборка по умолчанию включает MPI. На Windows нужен установленный MS-MPI, на Linux — компилятор MPI и его среда выполнения.

Из каталога постановки можно запустить `aero main:cfl=0.4 gas.txt:gamma=1.4 main:upw_coeff=0.8`. Значения действуют на один запуск. Поддерживаются параметры main.txt, gas.txt, cuda.txt, scheme.txt, implicit.txt и linear.txt, расширение можно опустить. При повторе ключа действует последнее значение. Без параметров каталогов ввод и вывод находятся в текущей папке.

Для неявного расчёта задайте в main.txt `time_scheme = BDF1` или `BDF2` и скопируйте [implicit.txt](templates/implicit.txt) в каталог постановки. BDF2 начинает с одного шага неявного Эйлера, затем учитывает длины двух соседних шагов. Контрольная точка BDF2 сохраняет предыдущий слой и длину принятого шага. При запуске из старой контрольной точки BDF2 снова начинает с одного шага BDF1.

Для выхода на стационар задайте в main.txt `time_scheme = steady`. Решатель делает псевдошаги неявного Эйлера с заданным CFL. В конце каждого шага он вычисляет `M = max |Rᵢₖ|/Vᵢ` по всем узлам, компонентам и процессам MPI. В implicit.txt выберите `steady_criterion = relative` для остановки при `M/M₀ <= steady_tol` или `absolute` для остановки при `M <= steady_tol`. При продолжении из контрольной точки M₀ вычисляется по загруженному полю. Равновесное начальное поле принимается сразу. При достижении `steady_max_steps` за запуск решатель записывает последние поля и сообщает о недостижении допуска. В режиме steady время в файлах означает псевдовремя.

В implicit.txt параметр `jacobian_update_every` задаёт частоту обновления пространственных производных. При 0 они обновляются на каждой поправке Ньютона, при 1 — на первой поправке каждого шага, при N — с интервалом N принятых шагов. Если шаг уже решил предиктор, собирать матрицу на этом шаге не требуется. При новом шаге вклад BDF в диагональ и его разложение обновляются перед первым линейным решением. Для начального приближения решатель пробует итерации Пикара с временной диагональю и проверяет каждую по полной невязке. При слабом уменьшении невязки вязкий предиктор дополнительно пробует часть поправки, выбранную по отношению норм. Каждую пробу решатель проверяет по полной невязке BDF. При неудаче он восстанавливает последнее принятое приближение и переходит к Ньютону.

Ньютон решает полный баланс на новом слое с потоком и реконструкцией из main.txt. В implicit.txt параметр `jacobian_flux` выбирает LF или Roe для матрицы поправки первого порядка. При `simplified_jacobian = on` фиксируется скорость диссипации LF или матрица диссипации Роу. Значение `off` включает полную производную этого потока. Диагональные блоки пространственной части определяются из баланса потоков. При запуске через MPI каждый процесс хранит строки своих узлов, а производные на общем ребре вычисляет один владелец.

BiCGSTAB принимает `preconditioner = BJ` или `CSGS`. CSGS использует раскраску сеточного графа на GPU и последовательный обход внутри подобластей на CPU. Между прямым и обратным проходами ранги обмениваются значениями на стыках. На GPU каждому процессу назначается карта. В отчётный шаг report показывает достигнутую относительную невязку Ньютона. [Алгоритм Магомедова и Горобца](https://cs.msu.ru/sites/cmc/files/docs/gorobec.pdf)

Для MP5 или MPWENO5 задайте `reconstruction = mp5` или `reconstruction = MPWENO5` в main.txt. В необязательном scheme.txt параметр `mp6_hybrid` задаёт вес ограниченной центральной поправки на полном шаблоне (0…1, по умолчанию 0). У MPWENO5 параметр `mpweno_ad_corr = on` включает антидиссипативную поправку к нелинейным весам, `off` выключает её. По умолчанию поправка включена. Пример запуска: `aero main:reconstruction=MPWENO5 scheme:mp6_hybrid=1 scheme:mpweno_ad_corr=on`.

При включённом гибриде MP6 обе акустические характеристики и энтропийная характеристика используют общий вес, а каждая поперечная — свой. В режимах `conservative` и `flux` солвер сначала восстанавливает значения слева и справа от грани по координатным осям. Затем он вычисляет поправку MP6. Для массы, нормального импульса и энергии (или их потоков) действует общий вес, для касательных составляющих импульса — местное ограничение. При стремлении `mp6_hybrid` к нулю поправка исчезает.

`upw_coeff` в main.txt масштабирует диссипативную часть потоков LF и Roe от 0 (центральный поток) до 1 (полная диссипация по умолчанию). Для CFL используется полная оценка скорости волн.

В EBR3 и EBR5 тот же параметр управляет реконструкцией на ребре. До ограничения солвер сохраняет среднее двух следов EBR и умножает их разность на `upw_coeff`. При 0 обе стороны получают общий центральный след, при 1 сохраняется чистая EBR. В режиме `flux` солвер смешивает таким способом и состояния, и физические потоки. На рёбрах с принудительными узловыми следами действует только множитель диссипации LF/Roe.


## Как проверить изменение

`make -j32 test` собирает и запускает модульные проверки. Для сборки и проверки MPI укажите `WITH_MPI=1`. Число после `-j` задаёт число одновременно выполняемых заданий сборки. Число вычислительных потоков задают `omp_threads` в постановке или `OMP_NUM_THREADS`.

Решение Visual Studio [aero.sln](msvs/aero.sln) собирает проекты тем же GNU Make. Для GPU передайте MSBuild параметр `/p:KokkosBackend=cuda`. Если MSYS2 установлен вне C:\msys64, задайте его корневой каталог в переменной среды MSYS2_ROOT.

`make -j32 programs` собирает программы. После этого `python qa/run.py --case sod_1d` сравнивает расчёт с точным решением задачи Сода. Команда `python qa/run.py` проходит всю матрицу. Варианты CUDA и MPI, расположение результатов и допуски описаны в [руководстве по QA](qa/README.md).

## Начальный расчёт с первым порядком

Параметр `t_fo` в `main.txt` задаёт время перехода от первого порядка по пространству во всех узлах к схеме `reconstruction`. Например, при `t_fo = 1` шаг, заканчивающийся в момент 1, выполняется с первым порядком на всех стадиях. Следующий шаг использует заданную реконструкцию и действующие локальные метки `low` или `on`. При `t_fo = 0` (по умолчанию) выбранная схема работает с начала расчёта. При продолжении из контрольной точки используется восстановленное время.

Для `steady` граница задаётся по псевдовремени. Критерий останова по невязке применяется для выбранной схемы; после переключения её начальная невязка задаёт отсчёт относительного снижения. Лимит числа псевдошагов относится ко всему расчёту.

## Стабилизация шага Эйлера

Параметр `stabilization` в `main.txt` применяется к уравнениям Euler с явным или неявным интегратором. По умолчанию задано `off`: используется обычный `cfl` из `main.txt`, недопустимое состояние останавливает расчёт. Для Linear используется `off`.

В режимах `cfl`, `low` и `on` начальное число Куранта задаёт `cfl_init` в `cfl.txt`. При неположительной плотности или давлении солвер восстанавливает принятый слой, делит CFL на `coeff` и повторяет тот же шаг. Значение ниже `cfl_min` завершает расчёт с ошибкой. После каждых `num_steps` последовательных успешных шагов CFL умножается на `coeff` до `cfl_max`. Требуются `0 < cfl_min <= cfl_init <= cfl_max`, `coeff > 1` и целое `num_steps >= 1`.

В режиме `low` или `on` со стороны отказавшего узлового контрольного объёма берётся значение первого порядка. Соседняя сторона ребра сохраняет свою реконструкцию. В режиме `low` все метки сбрасываются при подъёме CFL до 99 % максимума, в режиме `on` метки сохраняются и при продолжении из контрольной точки. В режиме `cfl` меняется только число Куранта и зависящий от него коэффициент MP.

В Report процесс 0 выводит `failed cells` (различные отказавшие узлы с предыдущего отчёта) и `first-order cells` (число узлов с принудительным первым порядком на отчётном шаге, либо все узлы для схемы `first_order`). При откате отдельно печатаются счётчики самой отказавшей попытки. Копии узлов в соседних MPI-процессах не увеличивают счётчики.

При запуске на GPU резервная копия для отката остаётся в памяти карты. На явной стадии Kokkos проверяет собственные узлы при их обновлении, на итерации Ньютона — после обмена полями с соседями. Процессор получает число отказов и локальные номера отказавших узлов, которые переводит в глобальную нумерацию для отчёта MPI.

## Управление запущенным расчётом

Сохраните команды в `control.tmp` в каталоге результатов (`--output`) и переименуйте его в **`control.txt`**. Процесс MPI с номером 0 забирает файл после первого принятого шага запуска и затем на шагах, кратных `control_every` из `main.txt`. По умолчанию это 16; значение 1 включает проверку на каждом шаге, 0 отключает её полностью. Дождитесь строки `Control applied after step` перед отправкой следующего файла. Для каждой применённой команды солвер печатает `Control accepted` с её именем и значением. Неизвестный ключ вызывает предупреждение, остальные команды применяются. При ошибке в значении известной команды солвер сообщает `Control rejected` и продолжает с прежними параметрами.

Каждая строка задаёт одно действие. Включайте только нужные строки.

```text
upw_coeff = 0.85
mp6_hybrid = 0.4
cfl = 0.5
cfl_min = 0.01
cfl_max = 1
cfl:num_steps = 20
cfl:coeff = 1.5
reset_fail
```

Оба веса принимают значения от 0 до 1. Команда `cfl` задаёт число Куранта следующего шага. При активной стабилизации изменение настроек CFL начинает отсчёт успешных шагов заново. Если меняются только границы, солвер приводит текущий CFL к новому диапазону. Явно заданный CFL должен в него попадать. Границы, множитель и интервал применяются в режимах `cfl`, `low` и `on`. В самом `cfl.txt` ключи называются `num_steps` и `coeff`.

Команда `reset_fail` снимает со всех узлов метки пониженного порядка, включая постоянные метки режима `on`. История отказов для очередного отчёта сохраняется. Условие `t_fo` продолжает действовать.

При обычном завершении и по команде `STOP` солвер запишет все зоны из `output.txt` и контрольную точку на принятом шаге, в том числе при `recovery_every_steps = 0`. Продолжить можно с `--recover`. Контрольная точка сохраняет введённые во время расчёта настройки, метки и предыдущий слой BDF2.
